## 1. 원칙

1. **판단은 한 곳에서 한다.** 같은 일을 두 노드가 정하지 않는다.

   | 무엇을 | 정하는 노드 | 보고 정하는 것 |
   |---|---|---|
   | 멈출지 | **정지 노드** | **1차:** 정지 입력(화면 버튼·키), Ctrl+C, 로봇 알람 — 4개. **1차 뒤(W066, 10/8):** 음성 '멈춰', 로봇 차례에 웹캠이 사람을 봄, 비전 신호 1초 끊김 |
   | 차례를 넘길지 | **작업 관리자** | **1차:** 화면 버튼 '내 차례 끝'(`turn_done`). **챌린지 ④:** 웹캠·손목 카메라 모두 손 없음 3초 + 칸 변화 |
   | 진행표(블록마다 놓였나) | **작업 판단** | 손목 블록 인식의 관측 결과 + 레시피. **1차:** 블록 있음·없음 + 높이. **1차 뒤(W100):** ±2 mm 판정·위층 보정 |
   | MoveIt2 장면(피할 물체 지도) | **장면 관리** | **1차:** 진행표(쌓인 블록) + 쥔 블록 붙이기·떼기 요청. **챌린지 ①:** 손목 손 찾기(사람 팔) |

   비전은 '있음·없음'과 관측 결과만 보낸다. 넘길지·멈출지는 위 노드가 정한다.
2. **메시지 방식은 섞는다.** 요청-결과가 있는 것(집기·놓기, 진행 확인, 다음 블록, 그리퍼, 장면 붙이기, 화면 명령)은 전용 서비스·액션(`d2_interfaces`). 상태 방송(진행표·상태·사건·알림·사람 감지 등)은 JSON 문자열(`std_msgs/String`).
3. **이름은 모두 `/d2/` 아래**에 파트·기능 앞머리를 붙인다: `/d2/hmi`, `/d2/safety`, `/d2/vision`, `/d2/task`, `/d2/motion`, `/d2/gripper`.
4. **단위.** 노드끼리는 m·rad·쿼터니언(자세 표현). 파일(레시피·CSV)은 mm. JSON 칸 이름에 단위를 붙인다(`dx_m`, `offset_mm`, `force_n`). `src/d2_bringup/config/robot.yaml`은 키 이름에 `_m`이 붙어 있으니 m로 적는다(9장).
5. **결과 형식.** 서비스·액션 결과에는 `success`(참·거짓) + `reason`(7장의 코드)을 넣는다.
6. **JSON 규칙.** 맨 앞 칸은 `"schema": "이름/1"`, 시각은 `stamp`(초, 소수). 형식을 바꾸면 `/2`로 올린다.
7. **좌표**는 로봇 기준 `base_link`. 설계 좌표는 조립 원점(T_base_from_cad, `robot.yaml`의 `assembly_origin`)으로 바꾼다. 바꾸는 계산은 작업 판단 한 곳에서 한다.
8. **블록 번호**는 레시피 block_id(예: `LV1_B001`)를 그대로 쓴다.
9. **장면은 장면 관리 노드만 고친다.** 다른 노드는 `apply_planning_scene`을 부르지 않는다. 쥔 블록은 `/d2/motion/scene/attach`로 부탁한다.
10. **출발 명령(`hmi/command start`)은 화면에서만 들어간다** — 화면 출발 버튼·키, 또는 음성 출발 요청 뒤 화면 확인 창의 [확인] (10/5 S-16). 음성만으로는 로봇이 움직이지 않는다. **잠금 풀기는 화면 '다시 시작' 버튼으로만** 한다. 1차 음성은 설계·모드 고르기와 출발 요청까지 한다. 보조 '멈춰'는 1차 뒤(W046, 10/8).
11. **멈출 때는 서기 궤적**(지금 자리에 0.3초 안에 서라는 아주 짧은 궤적)을 **제어기에 직접** 보낸다. MoveIt2 실행 취소만으로는 팔이 안 섰다(10/3 가상 시험, [TS-01](troubleshooting/TS-01_정지가_안_들음_R-01_v1_100415.md)). 정지 노드와 별도로, 로봇을 움직이는 프로그램은 자기 Ctrl+C·막힘 때도 서기 궤적을 먼저 보낸다.

- **돌리는 곳(10/5 S-15):** 서비스 PC 컨테이너는 1차 2개 — `vision`(웹캠 사람 감지, 웹캠은 `--device`) · `hmi`(웹 화면). 음성·작업 관리자·작업 판단은 서비스 PC 호스트. DB 컨테이너(`db-hmi`)는 1차 뒤(W051). 로봇 PC는 모두 호스트. 컨테이너는 host 네트워크라 이름·형식·통신은 호스트 노드와 같다.
- **기록기 노드는 1차에 없다**(10/4 15시 간소화 S-10). 작업 관리자가 run_id CSV를 직접 쓴다. 기록 전용 노드·토픽은 DB를 넣을 때(W051, 10/8 오전) 다시 본다.
- 실행 이름(안)은 이 문서에서 제안한 것이다. 패키지를 만들 때 담당이 바꿀 수 있고, 바꾸면 이 표를 고친다.
- 모든 노드는 어느 PC에서나 돌게 짠다(박힌 경로 없음). 옮기지 않는 것은 브링업과 정지 노드(로봇 PC), 그리고 카메라는 그 카메라를 처리하는 PC에 꽂는다.
- 웹 화면이 ROS 2와 이어지는 방법(rosbridge 또는 웹 서버가 직접)은 HMI가 정한다. 어느 쪽이든 아래 이름·형식은 그대로다.

## 4. 통신 표

### 4.1 토픽

JSON 토픽의 형식은 모두 `std_msgs/String`이고, 칸은 6장에 있다.

| 이름 | 형식 | 보내는 쪽 → 받는 쪽 | 주기 | 내용 |
|---|---|---|---|---|
| `/d2/hmi/intent` | JSON `intent/1` | 음성 → 작업 관리자 | 말할 때마다 | intent, design_id, mode, text(받아 적은 문장), confidence. 1차 intent = select_design·set_mode·start(출발 요청 — 작업 관리자가 화면 확인을 띄움, S-16) |
| `/d2/safety/stop_request` | JSON `stop_request/1` | 화면·키 → 정지 노드 (음성 멈춰는 **1차 뒤**, W066) | 누를 때마다 | source(web·key / voice는 1차 뒤), reason |
| `/d2/vision/human_zone` | JSON `human_zone/1` | 웹캠 사람 감지 → (1차는 받는 쪽 없음, 방송만. 정지 노드 구독은 **1차 뒤**, W066 10/8) | **10 Hz**, QoS RELIABLE · KEEP_LAST 1 · VOLATILE (10/4 한석형 확정) | zones{assembly, robot_supply, path, human_supply}: 있음·없음, stamp. 1차는 신호 내기까지(S-07) |

| `/d2/motion/halt` | JSON `halt/1` | 정지 노드 → 집기·놓기 | 멈출 때 한 번 | reason. 받으면 진행 중 목표를 취소한다 |
| `/d2/safety/state` | JSON `safety_state/1` | 정지 노드 → 모두 | 바뀔 때 (계속 방송 여부 미정) | stopped, locked, reason |

| `/d2/vision/hand_wrist` — **챌린지 ①** | JSON `hand_wrist/1` | 손목 손 찾기 → 장면 관리·작업 관리자 | 관측 자세에서 볼 때 (Hz 미정) | present, 손·팔 상자 목록(`base_link`, m). 1차에는 안 만든다(S-02·S-06) |
| `/d2/gripper/state` | JSON `gripper_state/1` | 그리퍼 노드 → 모두 | (Hz 미정) | width_m, grasped |
| `/d2/task/state` | JSON `state/1` | 작업 관리자 → 화면·정지 노드 | 바뀔 때 (계속 방송 여부 미정) | mode, state, turn(human·robot), run_id, block_id, message(안 — `WAIT_CONFIRM`일 때 확인 창 문장, S-16) |
| `/d2/task/notify` | JSON `notify/1` | 작업 관리자 → 화면 (음성 TTS는 **1차 뒤**, W052) | 알림마다 | id, text, block_id |
| `/d2/task/event` — **1차 뒤** | JSON `event/1` | 모든 노드 → (기록기) | 사건마다 | run_id, stamp, module, kind, block_id, value. **1차에는 기록 전용 토픽을 만들지 않는다**(S-10) — 작업 관리자가 자기 상태·결과를 run_id CSV로 직접 쓴다. DB를 넣을 때(W051) `/d2/log/…`로 다시 본다 |

## 6. JSON 형식 (`std_msgs/String`)

- 맨 앞 칸 `schema`, 시각 `stamp`(초). 길이 칸은 이름에 단위를 붙인다.
- **칸 세부는 보내는 쪽이 10/4 오후에 확정한다.** 아래 예시 한 줄은 4장 표의 칸으로 만든 안이다(값은 예). 확정되면 보내는 쪽이 이 장의 예시를 고친다.

| schema | 토픽 | 보내는 쪽 | 칸 |
|---|---|---|---|
| `progress/1` | `/d2/task/progress` | 작업 판단 | design_id, run_id, **obs_stamp**(관측 시각), blocks[ block_id, state(placed·empty·unknown), by(robot·human), **center_m·quat**(장면 관리용), **top_z_m**, dz_m, dx_m·dy_m(1차 null), judge(ok·over) ]. **관측할 때만 발행, 블록 11개 항상 전부**(안 본 블록은 이전 상태). **QoS: RELIABLE + TRANSIENT_LOCAL + KEEP_LAST 1** — 구독 쪽(장면 관리·화면·작업 관리자)도 같게(10/4 한석형 확정) |
| `state/1` | `/d2/task/state` | 작업 관리자 | mode, state, turn, run_id, block_id, message(안, S-16) |
| `event/1` — 1차 뒤 | `/d2/task/event` | 모든 노드 | run_id, stamp, module, kind, block_id, value. 1차 CSV 칸의 참고 안 |
| `notify/1` | `/d2/task/notify` | 작업 관리자 | id, text, block_id |
| `intent/1` | `/d2/hmi/intent` | 음성 | intent, design_id, mode, text, confidence |
| `human_zone/1` | `/d2/vision/human_zone` | 웹캠 사람 감지 | zones{assembly, robot_supply, path, human_supply} (참 = 있음) |
| `hand_wrist/1` — 챌린지 ① | `/d2/vision/hand_wrist` | 손목 손 찾기 | present, boxes(손·팔 상자, `base_link`, m) |
| `heartbeat/1` | `/d2/vision/heartbeat` | 비전 노드들 | node, last_frame_stamp |
| `stop_request/1` | `/d2/safety/stop_request` | 화면·키 (음성 멈춰는 1차 뒤) | source, reason |
| `halt/1` | `/d2/motion/halt` | 정지 노드 | reason |

- `intent/1`의 `mode`는 `start`·`set_mode`일 때 `auto`·`coop`를 넣고, 다른 의도는 null이다 (안, S-16에서 칸을 더함). `start`는 design_id·mode를 꼭 채운다.
- `state/1`의 `message`는 `WAIT_CONFIRM`일 때 확인 창에 띄울 문장이다(예: "벤치를 자동으로 쌓을까요?"). 다른 상태에서는 null (안, S-16).
- `hand_wrist/1`의 상자 표현(가운데 + 크기)은 안이다. 장면 관리가 원기둥으로 넣을지 상자로 넣을지에 맞춰 손목 손 찾기와 장면 관리가 정한다.

```text
# 번호 = 그림 구조 2의 번호. 이름 앞의 /d2/ 는 줄였다.
①  음성        → hmi/intent {intent: select_design, design_id: lv1_bench}   → 작업 관리자  (설계 고르기만, 로봇은 안 움직임)
②  화면        → hmi/command {cmd: start}                                    → 작업 관리자  (출발은 화면에서만 — 출발 버튼, 또는 음성 출발 뒤 확인 창 [확인] 8.4)
③  작업 관리자: 관측 자세로 이동 요청                                       (이동 명령 칸은 12장 — 아직 없음)

⑥  작업 판단   → task/progress (진행표)                                     → 장면 관리: 놓인 블록 blk_<id>를 장면에 넣기
⑦  작업 관리자 → task/next_block                                            → 작업 판단
⑧  작업 판단   → 답 {found: true, block_id: LV1_B003, supply_slot, pick_pose, place_pose, grasp: SIDE_25} → 작업 관리자
⑨  작업 관리자 → motion/pick_place (액션, 블록 1개 전체)                    → 집기·놓기
⑩  집기·놓기   → move_group: 경로 계획 → 공급 칸 위로 이동                  (step: approach)
⑪  집기·놓기   → gripper/command 열기 → 닫기 10 N (다 움직인 뒤 답)          (step: grasp)
⑫  집기·놓기   → motion/scene/attach {attach: true}                         → 장면 관리: 쥔 블록을 팔에 붙임
⑬  집기·놓기   → move_group: 블록 포함해 피하는 경로 → 조립 자리로 → 놓기   (step: lift → move → place)
⑭  집기·놓기   → motion/scene/attach {attach: false}                        → 장면 관리: 놓인 블록으로 되돌림
⑮  집기·놓기   → 결과 {success, reason, grip_width_m, duration_s}           → 작업 관리자   (step: retreat 뒤)
```

- 블록마다 손목 카메라로 배치를 확인한다(A8). **1차 = 블록 있음·없음 + 높이만**(S-05). 없거나 높이가 다르면 `OFFSET_OVER` → 멈추고 사람 호출. ±2 mm(`place_tolerance_m`) 판정과 위층 보정은 **1차 뒤**(W100, 10/8~10).
- 실패하면 7장 표대로 한다. 1차 기록은 작업 관리자가 단계마다 run_id CSV에 쓴다(`/d2/task/event`는 1차 뒤).
- 모드 바꾸기(음성·화면)는 쥔 블록을 놓은 뒤에 적용한다(D-25).

### 8.2 정지

![구조 3 정지 흐름](images/구조3_정지흐름_v1_100413.png)

```text
# 어떤 입력이든 정지 노드 한 곳에서 판단하고 제어기에 직접 세운다.
# 1차 정지 입력 4개 = 화면 정지 버튼 · 키 · Ctrl+C · 로봇 알람 (S-03). ②③은 1차 뒤(W066, 10/8).
①  화면 정지 버튼·키            → safety/stop_request {source, reason}      → 정지 노드   (음성 멈춰는 1차 뒤)
②  [1차 뒤] 웹캠 사람 감지      → vision/human_zone (늘 방송)                → 정지 노드
③  [1차 뒤] 비전 노드들         → vision/heartbeat (1초에 2번)               → 정지 노드
④  정지 노드: 멈출지 판단 — 1차: 정지 입력 / 로봇 알람 (Ctrl+C는 움직이는 프로그램이 스스로 서기 궤적)
              1차 뒤: 로봇 차례(task/state 의 turn)에 로봇 작업 영역(assembly·robot_supply·path)에 사람 / 비전 신호 1초 끊김(stop.vision_timeout_s)
⑤  정지 노드   → 서기 궤적 (지금 관절값, 0.3초)                             → dsr_moveit_controller (제어기에 직접)
⑥  정지 노드   → motion/halt {reason}                                       → 집기·놓기: 진행 중 목표 취소
⑦  정지 노드   → safety/state {stopped: true, locked: true, reason}         → 작업 관리자는 STOPPED, 화면은 "멈췄어요"
⑧  사람이 확인 → 화면 '다시 시작' 버튼 → safety/resume (std_srvs/Trigger)   → 정지 노드: 잠금 풀기
⑨  잠금 풀림   → 작업 관리자는 항상 진행 확인부터 다시 (8.1 ③)
```

- 펜던트 비상정지와 두산 충돌 감지는 이 흐름과 상관없이 늘 작동한다. **10/7 협동 실기의 안전은 펜던트·화면 정지 버튼·저속·충돌 감지로 한다**(웹캠 → 정지 연결은 W066, 10/8).
- 서기 궤적으로 `stop.first_wait_s`(2초) 안에 안 서면 두산 `move_stop`을 부른다. 그래도 안 서면 펜던트로 세운다. 실기 결과를 보고 2초를 줄인다(R-01).
- 집기·놓기가 halt를 받으면 진행 중 목표를 멈추고, 결과를 `success: false`, `reason` = halt의 reason으로 끝낸다(안).
- 화면 '다시 시작' 뒤 작업 관리자에게 이어 가라고 알리는 순서(안): `safety/resume` 성공 → `safety/state`에서 `locked: false` 확인 → `hmi/command {cmd: resume}`. 10/6 오전 개발 시작 전에 HMI·작업 관리자가 확인한다.

### 8.3 협동 모드 — 차례 넘기기 (1차 = 번갈아 하기)

![구조 4 협동 차례 흐름](images/구조4_협동차례흐름_v1_100413.png)

**1차(10/7): 차례 끝 = 화면 버튼 '내 차례 끝'** (10/4 15시 간소화 S-06). 손 감지로 자동 판단하는 것은 챌린지 ④.

```text
①  작업 관리자: 사람 차례 — 로봇은 관측 자세에서 멈춰 기다림 (task/state turn: human)
②  작업 관리자 → task/notify {text: "블록을 놓아 주세요"}                    → 화면
③  사람: 사람 공급 영역에서 블록을 가져와 설계도의 빈 자리에 2~3개 놓고 손을 뺌
④  사람 → 화면 버튼 '내 차례 끝' → hmi/command {cmd: turn_done}             → 작업 관리자: 로봇 차례로 (turn: robot)
⑤  작업 관리자 → task/notify: 출발 2초(turn.start_warning_s) 전 화면 알림    → 화면
⑥  작업 관리자: 진행 확인(있음·없음 + 높이) → 다음 블록 (8.1 ③~⑧)
⑦  작업 관리자 → motion/pick_place → 놓기 (8.1 ⑨~⑮)
⑧  로봇 차례에 사람은 로봇 작업 영역에 들어가지 않는다 — 1차 안전은 펜던트·화면 정지 버튼·저속·충돌 감지
⑨  다시 사람 차례로 → ①부터 반복
```

1차 뒤에 더하는 것:

```text
[챌린지 ④] 웹캠 human_zone + 손목 hand_wrist 둘 다 손 없음 3초(turn.hand_absent_s) + 칸 변화 → 작업 관리자가 자동으로 로봇 차례로
[챌린지 ①] 출발 전 손·팔이 보이면 → 장면 관리: human_* 를 장면에 넣기 → 피하는 경로로 계획
[W066 10/8] 로봇 차례에 사람이 로봇 작업 영역에 들어오면 → 정지 노드가 멈춤 (8.2 ②)
```

- 비전은 '손 있음·없음'만 보낸다. 넘길지는 작업 관리자, 멈출지는 정지 노드가 정한다.
- 화면 '내 차례 끝' 버튼(`hmi/command {cmd: turn_done}`)이 1차의 유일한 차례 끝 입력이다. 10/4 회의 때 '예비'였던 `human_done` 버튼을 이 이름으로 바꿨다(S-06).
- 양쪽이 막힌 칸이면(`BLOCKED_BOTH_SIDES`) 작업 관리자가 `task/notify`로 사람에게 부탁한다.
- 사람이 설계에 없는 자리에 놓았거나 많이 어긋나면 멈추고 다시 놓아 달라고 알린다(D-26).

### 8.4 음성으로 출발 — 화면 확인 한 번 (1차, 10/5 S-16)

음성만으로는 로봇이 움직이지 않는다. 작업 관리자가 화면에 확인 창을 띄우고, 사람이 [확인]을 눌러야 출발한다(STT가 무음에서 말을 지어낸 일 2/10, V-18).

```text
①  음성        → hmi/intent {intent: start, design_id: lv1_bench, mode: auto, text: "벤치 자동으로 만들어 줘"} → 작업 관리자
②  작업 관리자: 바로 움직이지 않는다. 설계·모드를 적용하고 시작 점검 → 상태 WAIT_CONFIRM (안)
③  작업 관리자 → task/state {state: WAIT_CONFIRM, message: "벤치를 자동으로 쌓을까요?"} → 화면: 확인 창 + [확인]
④  사람이 [확인] → hmi/command {cmd: start, design_id: lv1_bench, mode: auto}  → 작업 관리자: 출발 (8.1 ③부터)
⑤  30초 안에 [확인]이 없으면 → 취소, 확인 창을 닫는다 (안)
```

- [확인]은 새 버튼이 아니라 확인 창 안의 버튼이다. 화면 버튼 6개와 화면 출발 버튼은 그대로다. ④는 화면 출발 버튼과 같은 `hmi/command start` 길이다.
- 정지·다시 시작은 그대로 화면 버튼이다(음성 '멈춰'는 1차 뒤, W046).
- 1차 설계는 lv1_bench(벤치)뿐이다. 의자는 두 번째 가구(W074, 10/8~)라 예시 문장은 벤치로 쓴다.

| `stop.vision_timeout_s` | 비전 신호가 이만큼 끊기면 정지 — 1차 뒤(W066) | 1 | 정지 노드 |
| `stop.first_wait_s` | 서기 궤적 뒤 이 안에 안 서면 `move_stop` | 2 (실기 뒤 줄일 수 있음) | 정지 노드 |

- `place_tolerance_m`(±2 mm)은 로봇이 지킬 놓기 정밀도다. 블록이 7 mm 어긋나면 무너지는 '구조 유지 한계'와는 다른 값이다.
- 키 이름을 바꾸거나 빼는 것은 인터페이스 변경이다(머리말 변경 규칙). 값만 바꿀 때도 커밋 `영향:`에 읽는 노드의 파트를 적는다.
- 노드는 파일 경로를 하드코딩하지 않는다. launch가 파일 경로를 넘기거나, 패키지 경로(`get_package_share_directory`)로 찾는다. 파일을 어느 패키지에 둘지는 12장.

## 10. ROS 2 통신 설정

- **CycloneDDS로 통일한다**: 모든 PC·컨테이너에서 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`.
- `ROS_DOMAIN_ID`: 우리 팀은 **60번대**(60~69)를 쓴다. GPU PC = **60**. 번호가 같아야 서로 보이므로 함께 돌리는 PC·컨테이너는 모두 **60**으로 맞춘다(혼자 시험할 때 61~69를 각자 쓰는 것은 (안)).
- 컨테이너는 host 네트워크(`--net=host`)로 띄운다.
- 설치·확인 명령은 [개발 환경 설정](env/README.md)에 있다.

## 11. 가짜(mock) 노드 규칙

- **보내는 쪽이 만든다. 10/6 오전에 올린다(W034).** 토픽은 내보내는 쪽, 서비스·액션은 답하는 쪽이 만든다. 받는 쪽이 상대 없이 자기 노드를 시험할 수 있게 하려는 것이다.
- 실행 이름은 `mock_<진짜 실행 이름>`이고, 자기 파트 패키지 안에 둔다.
- **진짜와 같은 이름·같은 형식·같은 JSON 칸**을 쓴다. 그래서 진짜와 가짜를 동시에 켜지 않는다.
- 로봇·카메라·마이크·OpenAI 없이 돈다.
- 실패 코드(7장)를 일부러 낼 수 있게 한다. 인자 이름은 만드는 사람이 정한다.
- 인터페이스를 바꾸는 PR에는 가짜 노드 수정도 같이 넣는다.
- 10/6 저녁 기능별 통합 확인은 **2개**(10/4 15시 간소화 S-11): ① 동작 + 정지(W049, 벤치 11개를 가상으로 끝까지 + 정지) — 에뮬레이터 + 로봇 동작 진짜 노드 + 나머지는 진짜 또는 가짜 · ② 인식·판단 + HMI(W097) — 녹화 데이터 → 진행 확인 → 다음 블록 → 작업 관리자 → 화면.
