## 3. 역할 (D-03, 12시 PL 확정)

**로봇 동작 2명 · 비전 2명 · HMI 1명.** 파트 안의 일은 두 사람이 같이 맡고, 누가 무엇을 할지는 두 사람이 정한다. 11시 희망 조사와 여러 배정 안을 본 뒤 PL이 정했다.

| 파트 | 담당 | 포함 묶음 | 1차(10/7)까지 핵심 | 챌린지 |
|---|---|---|---|---|
| **로봇 동작** | 박진용, 한세교 (+CAD 한세교) | 로봇 셀 · MoveIt 실행기 · 정지 · MoveIt 장면 · MoveIt 집기 · 놓기 · 안전 감시 · 인프라 · 통합 | R-01 재시험, 그리퍼 다시 재기 · 그리퍼 노드, 작업영역 · 공급 영역 좌표 · 안전 설정, MoveIt2(TCP 반영 · R-03 · 집기 · 놓기), 정지 노드, 브링업 · 저장소 · 설정 파일 · PC 부하, CAD 조립 시험 · CAD 문제 고치기 | ① 갈아타기 → 동시 작업 · ② 흩어진 블록 집기 · ④ 떨어뜨리기 + 정돈 · 두 번째 가구 CAD |
| **비전** | 민범진, 한석형 | 손목 보정 · 녹화 · 웹캠 사람 유무 · 비전 · 작업 판단 · 작업 관리자 | 데이터 녹화, 손목 보정 · V-15, 웹캠 설치 · 사람 유무, 블록마다 배치 확인 · 손 찾기 · 차례 끝, lv1_bench 레시피 · 진행표 · 다음 블록, 전체 흐름 상태표 노드 | ① 손 위치 · ② 흩어진 블록 찾기 · ③ 안정성 검사기 |
| **HMI** | 황인재 (+PL) | 화면 · DB · 음성 · LLM | 웹 화면 최소형(설계 선택 · 출발 · 정지 · 진행), 화면 설계 → DB 제품, 웨이크워드 · STT · 의도 분류 · 음성 멈춰 | ③ 말 → 레시피 만들기(LLM) · TTS · DB · 대시보드 |

- 파트 안 나누기는 두 사람이 정한다(참고 예: MoveIt2는 박진용 = 실행기 · 정지 + 집기 · 놓기, 한세교 = 장면 · 쥔 블록 · 허용 충돌. 비전은 민범진 = 블록 인식 · 손목 보정 · 녹화, 한석형 = 사람 감지 · 차례 끝).
- **백업:** 박진용(10/10 없음) → 한세교가 MoveIt2를 이어 받음 · 비전 두 사람은 서로 백업.
- **PR 승인:** 황인재 · 한세교(팀 규칙 ⑦).
- **HMI:** HMI는 **황인재 혼자** 맡는다(10/4 PL 결정 — 팀 규칙 ③의 예외).

## 5. 인터페이스 (D-06, 26개 결정)

역할이 정해진 뒤 회의에서 모듈 사이 약속을 정했다. 전체 표 · 메시지 파일 · 칸은 [인터페이스 문서](../02_인터페이스_IRD_v3_100821.md)가 정본이다. 아래는 묶음별 요약이다.

| 묶음 | 정한 것 |
|---|---|
| 메시지 방식 | **섞기:** 요청-결과(집기 · 놓기, 진행 확인, 다음 블록, 그리퍼, 장면 붙이기, 화면 명령)는 전용 서비스 · 액션, 상태 방송(진행표 · 상태 · 사건 · 알림 · 사람 감지)은 JSON 문자열. JSON 맨 앞에 `"schema": "이름/1"`, 시각은 `stamp`(초). **이유:** 칸이 자주 바뀌는 상태 방송은 JSON으로 두어 다시 빌드하지 않고 고치고, 틀리면 위험한 요청-결과는 전용 메시지로 빌드 때 형식을 검사한다(10/4 회의 자료 5.3). **(→ 10/8 E-69: 형식 이름 = `<이름>/<앞>.<뒤>` — 앞 +1 = 깨지는 변경, 뒤 +1 = 호환 확장. 점 없는 `이름/1`은 다음에 바뀔 때 옮김)** |
| 이름 · 패키지 | 모두 **`/d2/` 아래** + 파트 앞머리(`/d2/hmi` · `/d2/safety` · `/d2/vision` · `/d2/task` · `/d2/motion` · `/d2/gripper`). 전용 메시지는 **`d2_interfaces`** 하나(`PickPlace.action` · `GripperCommand` · `CheckProgress` · `NextBlock` · `HmiCommand` · `SceneAttach`) |
| 단위 · 번호 · 좌표 | 노드끼리 m · rad · 쿼터니언, 파일은 mm. JSON 칸 이름에 단위(`dx_m` · `force_n`). 블록 번호는 레시피 block_id(`LV1_B001`). 좌표는 `base_link`, 설계 좌표는 조립 원점으로 바꾼다 **(→ 10/7 E-52 · 10/8 E-60 · E-69: 블록 번호 = `<설계 ID 대문자>_<역할>[_<옵션>]_<부품>_<블록>`(예 `001_CHAIR_BENCH_LEG_001_01`), 이름은 변환기 ①이 AI의 `role` · `part`에서 계산)** |
| 결과 · 실패 이유 | 서비스 · 액션 결과는 `success` + `reason`. 코드 8개: `PLAN_FAILED`(다시 계획 1번 → 호출) · `GRASP_FAILED`(1번 더 → 다음 칸 → 호출) · `SLOT_EMPTY`(다음 칸) · `OFFSET_OVER`(멈추고 호출) · `BLOCKED_BOTH_SIDES`(사람에게 부탁) · `HUMAN_IN_ZONE` · `VISION_LOST`(STOPPED) · `TIMEOUT`(호출) |
| 판단은 한 곳에서 | 멈출지 = **정지 노드** · 차례를 넘길지 = **작업 관리자** · 진행표 = **작업 판단**(주인) · MoveIt2 장면 = **장면 관리**(유일하게 고치는 노드). **→ S-02 · S-07:** 1차 장면 = 쌓인 블록 + 쥔 블록만(사람 팔은 챌린지 ①), `human_zone`은 1차에 정지 노드가 구독하지 않는다(W066부터) |
| 정지 경로 | 정지 노드가 서기 궤적을 **제어기에 직접**(`FollowJointTrajectory`, 지금 관절값 · 0.3초), 집기 · 놓기에는 `/d2/motion/halt`(→ 10/6 S-26으로 바뀜: `safety/state` 하나). 잠금은 화면 **'다시 시작'으로만** 푼다(`/d2/safety/resume`) |
| 화면 · 음성 | 출발(`start`)은 **화면에서만**(`/d2/hmi/command`). 음성은 뜻(`/d2/hmi/intent`)만 보낸다. **→ S-06:** `/d2/hmi/command`의 사람 차례 끝 값은 `turn_done`(옛 `human_done`). **→ S-16으로 바뀜(10/5):** 음성 의도에 `start`를 더한다. 작업 관리자는 이것을 화면 출발 버튼(`hmi/command start`)과 똑같이 받는다. 출발 = 화면 버튼 또는 음성 |
| 동작 묶음 | 집기 · 놓기는 **블록 1개 전체 액션**(`/d2/motion/pick_place`), 실행기는 같은 프로그램 안 클래스. 그리퍼는 **다 움직인 뒤 답**(`/d2/gripper/command`) |
| 설정 · 기록 | 설정은 **`src/d2_robot/d2_bringup/config/robot.yaml` 하나**(보정 값만 따로). 기록은 **기록기 노드 하나**가 `/d2/task/event`를 받아 남긴다. **→ S-10으로 1차 범위 바뀜(D-35 기록):** 1차는 기록기 노드 없이 작업 관리자가 run_id CSV를 직접 쓴다. 기록 전용 토픽(`/d2/task/event` · `/d2/log/…`)과 기록기는 DB를 넣을 때(W051) 다시 본다 **(→ 10/7 W121: `/d2/hmi/save_build`(`build/1`)로 정함 — 10/8 E-57)** |
| 통신 · 실행 환경 | ROS 2 통신은 **CycloneDDS로 통일**, 모든 PC · 컨테이너 같은 `ROS_DOMAIN_ID`(번호는 다른 팀과 안 겹치게 정함). Docker 범위는 §4. 웹 연결(rosbridge / 웹 서버 직접)은 HMI가 정해 개발 |

- **PC 이름(10/5 22시 PL):** '서비스 PC'를 **'운영 PC'**로 바꿨다. ROS 통신의 '서비스'와 헷갈려서다. launch 이름(안)도 `ops_pc.launch.py`. 이 문서의 이전 줄도 새 이름으로 고쳤다.
- **1차 설계는 lv1_bench(벤치)뿐이다.** 의자는 두 번째 가구(W074, 10/8~)다. 음성 예시 문장은 벤치로 쓴다.
