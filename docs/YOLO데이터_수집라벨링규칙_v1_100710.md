## 1. YOLO가 맡는 일 — "블록이 어디 있고 어떤 모양으로 보이나"까지만

```text
손목 컬러 사진 → YOLO seg → 블록마다 윤곽(마스크)
                     ↓ (여기부터는 YOLO가 아님 — 깊이로 계산, SDD §6.11)
윤곽 안 깊이 → 작업면 기준 윗면 높이 15 · 25 · 75 mm → 자세(눕힘 · 옆세움 · 세움, 더 높으면 포개짐)
            → 양 끝 높이 차 ≥ 5 mm면 tilted(한쪽이 걸쳐 기울어짐, E-43 — 고르지 않음)
            → 긴 변 방향 = yaw → 중심 (x, y) → 양옆 틈 → find_blocks 결과
```

| 정할 것 | 안 | 이유 |
|---|---|---|
| 모델 종류 | **seg(윤곽) — 정함(PL 10/7)** · `yolov8n-seg` 또는 `yolo11n-seg`(가장 작은 n, 로봇 PC CPU 추론) | 박스는 기울기(yaw)를 모르고, 겹치면 두 박스가 거의 같아진다. 회전 박스(obb)는 yaw는 나오지만 가려진 곳까지 덮는다. seg는 보이는 모양 그대로라 X자 겹침 · 포개짐을 나눈다 — 그림 [YOLO 종류 비교](images/YOLO종류_비교_v1_100708.png) |
| 클래스 | **`block` 1개 — 정함(10/7 비전 동의, W086 결과 보고 필요하면 다시)** | ① 자세(눕힘 15 · 옆세움 25 · 세움 75 mm)와 기울어짐은 깊이로 확실히 나온다 — 같은 것을 YOLO에 또 시키지 않는다 ② 자세별로 나누면 150장이 셋으로 쪼개져 장수가 모자라고, 세움처럼 드문 클래스는 잘 안 배운다 ③ 포개짐 · 기울어짐처럼 애매한 블록에서 라벨하는 사람마다 클래스가 달라진다. 3개(`flat` · `edge` · `stand`)로 나누는 것은 깊이가 자주 틀릴 때의 대안 — 위에서 본 윗면이 75×25 · 75×15 · 25×15라 구분은 된다 |
| 입력 크기 | 640 × 480 그대로(`imgsz 640`) | 추론 때 카메라 설정과 같게. 약 500 mm 위에서 1 px ≈ 0.82 mm → 블록 긴 변 약 91 px, 짧은 변 18~30 px(W018) |

## 2. 수집 규칙 (W114 촬영, 10/8 오전)

### 2.1 카메라 · 자세

| 규칙 | 내용 |
|---|---|
| 카메라 | 손목 D435i, **컬러 640 × 480 + 컬러에 맞춘(align) 깊이 640 × 480**. 노출 · 화이트밸런스는 추론 때와 같게(자동 그대로) |
| 자세 | **observe_supply(W134)** 하나. W134가 아직이면 공급 영역 전체가 보이는 같은 높이(카메라 → 작업대 약 500 mm, ±5 cm)에서. **추론 때와 다른 높이 · 각도 사진은 섞지 않는다** |
| 같이 저장 | 같은 번호로 ① 컬러 PNG ② 깊이 16비트 PNG(mm) ③ 관절값 · 카메라 자세(TF) json — W022 녹화와 같은 묶음 |
| 화면에 넣지 않을 것 | 사람 손 · 팔(블록을 다 놓고 손을 뺀 뒤 찍는다), 로봇 그리퍼 그림자가 블록을 덮는 사진 |

### 2.2 장면 만들기 — 10장면 × 약 15장 = 약 150장

| 규칙 | 내용 |
|---|---|
| 장면 수 | 10장면(E-38). 장면마다 블록을 새로 흩뿌린다 |
| 블록 수 | 장면마다 6~15개, 장면마다 다르게 |
| 자세 섞기 | 대략 눕힘 절반 · 옆세움 ¼ · 세움 ¼ |
| 어려운 경우를 장면마다 넣기 | 포개짐(블록 위 블록) 2~3곳 · X자 겹침 1~2곳 · **한쪽이 다른 블록에 걸쳐 기울어진 블록 1~2개(E-43)** · 딱 붙은 두 블록(틈 없음) 1~2쌍 · 공급 영역 경계에 걸친 블록 1~2개 |
| 한 장면에서 여러 장 | 첫 사진을 찍고 → **위에 있는 블록부터 1~2개씩 걷어 내며** 다시 찍는다(로봇이 실제로 집는 순서와 같은 상태가 나온다) → 다 걷을 때까지 약 10~15장 |
| 조명 | 10장면 중 3장면 이상은 조명을 바꿔서(실내등 일부 끄기 · 블라인드 등). 시연장 조명을 모르니 한 가지 조명만 쓰지 않는다 |
| 빈 공급 영역 | 블록 0개 사진 5장 이상(WAIT_SUPPLY 상황 — 블록 없는 배경도 배워야 헛것을 안 찾는다) |
| 비슷한 사진 금지 | 같은 상태에서는 1장만. 녹화 영상에서 뽑을 때도 블록 상태가 바뀐 프레임만 |
| 녹화(W022) 사진 | 조립 영역의 정렬된 블록이라 흩뿌린 장면과 다르다 → 보조로, 전체의 ¼ 이하 |

**시간 어림:** 1장에 블록 걷기 포함 약 15초 → 150장 약 40분. W114는 10/8 오전 2칸에 스캔 촬영과 같이 있다 — 흩뿌린 장면을 먼저 찍는다(안).

### 2.3 파일 이름 · 저장

| 규칙 | 내용 |
|---|---|
| 이름 | `s<장면 2자리>_<번호 3자리>_<조명 a/b>_<color/depth/pose>.<png/json>` — 예: `s03_007_a_color.png` |
| 저장 위치(PL 10/7) | **드라이브 [`YOLO_흩어진블록`](https://drive.google.com/drive/folders/1JGy5WsqshCcVbKk0Jr9iYZHGGn2Sg8w3) 한 곳** — `1_원본_W114`(컬러 · 깊이 · 자세) · `2_라벨_Roboflow`(내보낸 데이터셋 zip) · `3_모델`(`best.pt`, 이름에 날짜 · 장수) · `4_시험_V-52`(시험 장면, 학습에 안 씀). 저장소에는 넣지 않는다(용량). 노드는 모델 파일 경로를 설정으로 받는다 |

## 3. 라벨링 규칙

| 규칙 | 내용 |
|---|---|
| 무엇을 | **화면에 보이는 블록은 어디 있든 전부** 라벨한다(공급 영역 밖, 조립 영역 블록 포함). 하나라도 빠지면 모델이 "블록인데 배경"으로 배운다 |
| 윤곽 | 블록이 **보이는 부분만** 따라 그린다. 가려진 부분을 짐작해 그리지 않는다. 위에서 보이는 옆면도 포함(블록 실루엣 전체) |
| 가려져 두 조각으로 보이면 | 큰 조각 하나만 그 블록으로 라벨 |
| 화면 끝에 잘린 블록 | 보이는 부분만 라벨 |
| 너무 많이 가려진 블록 | 사람이 보고 블록인지 모르겠으면 라벨하지 않는다(대략 보이는 면이 블록 윗면의 ⅓ 미만) |
| 도구(PL 10/7) | **Roboflow**(웹) — **민범진이 프로젝트를 만들고 라벨을 이끈다**(한석형 · 황인재 초대). 다 끝나면 민범진이 내보낸 데이터셋을 드라이브 `2_라벨_Roboflow`에 올린다. 프로젝트 종류 *Instance Segmentation*, 클래스 `block`. 블록을 클릭하면 윤곽을 따 주는 **Smart Select**(SAM 자동 윤곽)를 쓰고 손으로 모서리만 다듬는다. 내보내기는 버전(Generate)을 만든 뒤 Export → **YOLOv8 또는 YOLOv11 형식**(윤곽 다각형 포함, Ultralytics). Roboflow가 내보내는 사진은 압축되므로 원본은 드라이브 것을 정본으로 둔다. 무료 판은 데이터가 Roboflow 학습에 쓰일 수 있다(설정에서 끌 수 있음 — 젠가 사진이라 문제는 없음) |
| 나누기 | **민범진 중심**, 한석형 · 황인재가 남는 장면을 장면 단위로 나눠 맡는다(누가 몇 장면인지는 민범진이 정함). 윤곽은 모두 약 750개(150장 × 사진 한 장에 평균 약 5개 — 걷어 내며 찍으므로 처음 개수의 절반쯤) — 자동 윤곽으로 한 사람이 다 하면 약 1.5~2시간(어림) |
| 검사 | 라벨한 사람이 아닌 사람이 장면마다 2장씩 다시 본다 — **빠진 블록 0개**가 기준 |

## 4. 나누기 · 학습 · 시험

| 규칙 | 내용 |
|---|---|
| 학습 · 검증 나누기 | **장면 단위로** 나눈다(사진 단위로 섞지 않음 — 같은 장면 사진은 서로 닮아 점수가 부풀려진다). 안: W114 10장면 중 학습 8장면 · 검증 2장면. Roboflow에서 나눌 때도 장면 번호(`s03` 등)로 묶어 나눈다 |
| V-52 시험(10장면 ≥ 90 %) | **시험 데이터는 따로 빼 둔다** — 학습 · 검증에 한 번도 안 쓴 **새 장면 10개**(10/10~11 W086 실기 때 새로 흩뿌려 찍음)를 `4_시험_V-52`에만 둔다. 학습에 쓴 장면으로 시험하면 답을 외운 문제를 다시 푸는 것이라 점수가 부풀려진다 |
| 학습 | Colab GPU, `imgsz 640`, 약 100 epoch, 약 1시간(E-38). 증강은 기본값(뒤집기 · 색 · 모자이크) + 회전(위에서 보는 사진이라 돌려도 같은 장면) |
| 추론 | 로봇 PC CPU — `find_blocks` 한 번에 사진 1장이라 속도 부담이 적다. W053에서 잰 CPU 여유 안에서 |
| 결과 보여 주기(안) | 그림 두 장을 나란히 — ① 컬러 사진 위에 YOLO seg 윤곽을 **깊이로 내린 판정 색**으로 칠하고(집을 수 있음 · 기울어짐 · 걸친 블록 · 가려짐) 블록마다 자세 · 높이 · yaw 글자 ② 깊이 색 지도(높을수록 빨강 — 기울어진 블록은 한쪽 끝으로 색이 변함). YOLO가 찾은 것과 깊이가 판단한 것을 한눈에 보여 준다 — [그림](images/흩어진블록_찾기결과화면_안_v1_100709.png) |
| 결과 기록 | `docs/test-reports/`에 학습 장수 · 검증 점수(mAP) · V-52 결과 · 틀린 사진 몇 장 |

## 6. 정한 사람 · 때

모델 seg · 도구 Roboflow · 드라이브 저장(PL 10/7 09시), 클래스 `block` 1개(비전 동의 10/7 10시) · Roboflow는 민범진이 만들고 라벨을 이끌며 한석형 · 황인재가 남는 장면을 나눔(민범진 제안을 PL이 섞어 정함 10/7 10시). 학습(`3_모델`)을 누가 할지는 비전이 정한다. 남은 질문 없음.
