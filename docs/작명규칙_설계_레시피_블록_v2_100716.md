# 작명 규칙 — 설계 · 레시피 · 블록 · 한세교 10/7

> **10/7 16시 PL: 이 v2를 결정 E-52로 정함.** IRD 2장(블록 이름 · design_id) · 6장(`cad_structure/1.0` · `cad_recipe/1.0`)에 옮겼다. 설계 이름은 블록 이름에서 잘라 내지 않고 `CheckProgress.design_id` 칸으로 넘긴다(㉮). 7장 절차의 마감은 **10/8 저녁**(1차 판정은 E-50으로 없어짐). 파트별 일은 일정표 W137~W141.

> 로봇 동작(한세교)이 정한 이름 규칙과, 다른 파트와 같이 정해야 할 것을 한 장에 모았다. 확정되면 IRD 2장에 옮긴다.
> **v2(10/7 16시):** 블록 이름을 놓는 순서(`B001`)에서 **구조를 알 수 있는 역할 이름**(`LEG_001_01`)으로 바꾸는 안, CAD 핸들 · 해시는 검증용 메타데이터, 책상 2종(003 · 004), 부품 규격 · CAD 안 이름 · 옛 잡기 이름, 레시피 두 파일, 파일 이름 E-44 충돌, IRD 반영 절차(7장)를 더했다.

## 1. 왜 정하나

- 같은 블록을 부르는 이름이 여럿이었다: `LV1_B001`(옛 IRD 예시) · `DXF_INSERT_3E`(레시피 안) · `001_CHAIR_BENCH_B001`(10/7 규칙).
- `DXF_INSERT_3E`는 CAD 내부 번호(DXF 핸들)라서 **CAD를 다시 저장하면 바뀐다.** 사람 · 노드 사이 이름으로 쓸 수 없다.
- `B001`(놓는 순서)은 **이름만 봐서는 구조에서 어디인지 모르고**, 조립 순서를 바꾸면 이름까지 바뀐다. 블록 이름은 구조(무엇이 어디에)에 붙고, 순서는 조립 방법이 따로 정해야 한다.
- 젠가에서는 **부품(다리 · 좌판) 하나가 블록 여러 개**다. 이름도 부품 → 블록 두 단계여야 한다.

## 5. 레시피 두 파일 (안)

```jsonc
// recipes/001_CHAIR_BENCH_structure.json — 무엇을 어디에 (로봇과 무관, 생성 · 스캔 · 검사 묶음과 같은 구조)
{ "schema": "cad_structure/1.0", "model_id": "001_CHAIR_BENCH",
  "source_cad": {"filename": "001_chair_bench.dxf", "sha256": "342a…"},
  "parts":  [{"part_id": "PART_001", "size_mm": [75, 25, 15]}],
  "blocks": [{"block": "LEG_001_01", "part_id": "PART_001",
              "center_mm": [-25, 0, 7.5], "R": [[0,-1,0],[1,0,0],[0,0,1]],
              "cad": {"handle": "3E"}}] }

// recipes/001_CHAIR_BENCH_recipe.json — 어떻게 (순서 · 잡기 · 받침)
{ "schema": "cad_recipe/1.0", "model_id": "001_CHAIR_BENCH", "structure_sha256": "…",
  "steps": [{"block": "LEG_001_01", "sequence": 1, "stage": 1,
             "grasp": "FLAT_SHORT", "grasp_axis": "WIDTH", "supports": []}] }
```

- 두 파일은 블록 이름으로만 잇는다. 조립 파일의 `structure_sha256`으로 '이 조립 방법은 이 구조 파일에 대해 쓴 것'을 확인한다.
- 칸 이름(`block` · `block_id` 등)은 IRD 확정 때 정한다 — 지금 IRD · 코드의 `block_id` 칸은 전체 이름(`<모델ID>_…`)을 담는다.

## 7. IRD에 옮기는 절차 (1차 판정 뒤 W121)

블록 이름 · 레시피 파일 구조 · 파일 이름은 IRD 인터페이스(2장 `block_id` · `design_id`, 레시피 형식)를 바꾸므로 **PL 확인과 받는 파트 확인**을 받고 한 번에 바꾼다. 읽는 쪽이 멈추지 않게 E-44(형식 이름)와 같은 순서로 한다.

1. **PL께 안 보내기** — 이 문서 2 · 3 · 4 · 5장 + 파일 이름 재검토 요청을 묶어서. 정해지면 IRD 2장(52 · 54행)과 레시피 형식 절에 옮긴다.
2. **읽는 쪽이 옛 · 새 둘 다 받게** — 로봇 동작(`motion_math.recipe_blocks` · `scene_manager_node` · `run_recipe` · `d2_bringup/setup.py`), task(한석형 — `recipe_to_blocks` · `task_node` · 시험), 비전(민범진 — `wrist_block` · `mock_wrist_block`).
3. **레시피 도구 · 레시피 4종을 새 형식으로**(한세교) — CAD 3종 안 블록 이름도 바꾼다.
4. **옛 형식 읽기를 뺀다**(각 파트).
