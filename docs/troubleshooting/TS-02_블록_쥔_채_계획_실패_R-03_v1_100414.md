# TS-02 · 블록을 쥔 채 MoveIt2 계획이 바로 실패 (R-03, 10/3 17:18)

| | |
|---|---|
| 날짜 | 2026-10-03 17:18 · 실기 · 박진용 (`pick_place_avoid.py` 실행 기록) |
| 증상 | 블록을 70 mm 폭으로 잡은 뒤(42.24 s) '플레이스 위로' 가는 계획이 **FAILURE로 60초 내내** 실패했다. 돌려놓으려고 픽 위(거의 같은 자세)로 가는 계획도 60초 동안 실패했다. 요청이 **약 0.01초 만에** 돌아왔다(49.59 → 49.60 s, 109.72 → 109.73 s). 목표 자세 검사는 통과했고, 장면의 장애물은 0칸이었다 |
| 피해 | 없음(로봇은 블록을 쥔 채 서 있었다) |
| 영향 | **놓기 전부.** 놓기는 늘 블록을 쥔 채 계획하므로, 이것이 안 풀리면 MoveIt2로 놓을 수 없다 → 1차 완료 기준(lv1_bench 11개)이 걸려 있다. 10/3 실기 기록 5개 중 블록을 쥔 채 이동을 끝낸 것은 없다. 10/3 저녁의 실기 성공(V-07)은 **빈 그리퍼로** 사람 팔을 피한 이동이었다 |

## 원인 (추정 — 아직 확인 전)
- 0.01초 만에 거절됐으므로, 길을 찾다가 못 찾은 것이 아니라 **요청 단계에서 거절**된 것으로 보인다(추정).
- 가상(`jenga_coop`)에서는 같은 '잡고 → 쥔 블록을 팔에 붙이고(attached object) → 계획'이 9번 모두 성공했다. 그래서 **실기 구성 차이**를 의심한다. 후보:
  1. **쥔 블록과 손가락 · 받침 · 옆 블록 사이 허용 충돌(ACM, 닿아도 되는 쌍) 설정** — 먼저 볼 곳. 쥔 물체를 붙일 때 흔히 생기는 원인이다(Gemini 검토 지적, 추정)
  2. 공구 아래 방향 자세 제약
  3. 작업대 여유 상자(작업대를 부풀려 넣은 충돌 물체)
  4. 그리퍼 관절값 · 카메라 모델과 붙인 블록의 겹침
- 원인이 확인되기 전까지 단정하지 않는다.

## 조사 방법
1. `move_group` 로그에서 거절 이유를 찾는다.
2. 안 나오면 가상에서 같은 순서(70 mm 닫기 → 붙이기 → 계획)로 재현하고, 위 후보를 하나씩 빼 본다.
3. 10/4 [로봇 9] CAD 조립 시험(lv1_bench 레시피 그대로)에서 실기로 다시 확인한다.
- 담당: 로봇 동작 파트(박진용 · 한세교). 쥔 블록 · 허용 충돌은 장면 관리 쪽 일이다(장면 관리 노드만 장면을 고친다 — [IRD](../02_인터페이스_IRD_v3_100812.md) `/d2/motion/scene/attach`).

## 임시 대책
- 쥔 채 계획이 실패하면 OMPL을 다시 부르지 말고, **방금 올라온 수직 경로를 되짚어 내려놓는다**(사람이 확인한 뒤 느린 속도로).
- 실기에서 계속 끊기면 마지막 접근 · 놓기만 두산 명령으로 바꾼다(A2의 예비안).
- 놓는 마지막 순간에는 블록끼리 닿는 것만 허용한다(M-05). 이것도 같은 허용 충돌 설정에 들어간다.

## 해결 기준
블록을 쥔 채 공급 → 조립 계획이 **10번 연속 성공**(FR-M05 — [01 요구사항](../01_요구사항_BR-SR_v3_100812.md)).
