# TS-01 · 정지가 안 들음 — MoveIt 취소 · `move_stop` · Ctrl+C로 로봇이 안 섬 (R-01, 10/3)

|---|---|
| 날짜 | 2026-10-03 가상 시험(박진용) · 10/3 밤 코드 점검 · 10/4 오전 수정안 · 가상 재시험 · **10/4 오후 실기 확인(박진용, 일정표 W010)** |

## 원인
1. **이미 제어기에 보낸 궤적은 계속 움직인다.** MoveIt2는 계획한 궤적을 제어기(`dsr_moveit_controller`)에 흘려보낸다. MoveIt 쪽에서 실행을 취소하거나 프로그램을 끝내도, 제어기는 받은 궤적을 끝까지 실행했다(10/3 · 10/4 가상). 두산 `move_stop`도 이 궤적은 세우지 못했다. 제어기에 '지금 자리에 서기' 궤적(지금 관절값 · 0.3초)을 새로 보내야 섰다.
2. **Ctrl+C 때 ROS가 먼저 꺼진다.** `rclpy.init()` 기본값은 Ctrl+C(SIGINT)를 받으면 ROS를 먼저 끈다. 그 뒤 보내는 정지 명령은 `publisher's context is invalid`로 실패한다. `SignalHandlerOptions.NO`로 시작하면 성공했다(10/3 밤 Jazzy rclpy로 확인).
3. **실패를 삼켰다.** 정지 실패를 잡아서 숨기고 성공처럼 출력했다.

10/4 실기에서 '동작이 끝난 뒤에야 선' 것(증상 ④)도 1번과 같은 꼴로 본다(추정 — 실기 원인 분석은 기록 전).

## 해결

두 단계로 풀었다. 먼저 가상에서 원인과 고치는 방법(서기 궤적)을 확인했고, 그다음 박진용이 실기 코드에 Ctrl+C 즉시 정지를 넣어 실제 로봇에서 확인했다.

### 1단계 — 가상: 서기 궤적 (R-01 수정안, 10/4 오전)
`safe_stop.py`(`init_ros()` + `SafeStop.stop()`)를 만들어 박진용 코드 4개에 넣은 수정안이다. 자세한 것은 [R-01 가상 정지 시험](../test-reports/R-01_정지수정_가상시험_v1_100415.md).

```
init_ros()         rclpy 를 SignalHandlerOptions.NO 로 시작 → Ctrl+C 를 우리가 받는다
stop() 순서        ① 서기 궤적(지금 관절값 · 0.3초)을 제어기에 직접
                   ② MoveIt 실행 취소
                   ③ 관절 변화로 '섰다'를 확인
                   ④ 2초 안에 안 서면 두산 move_stop → 2초 더 확인
                   ⑤ 그래도 안 서면 '펜던트 비상정지!'를 크게 띄움 (실패를 삼키지 않음)
                   정지 중에 Ctrl+C 를 또 눌러도 정지가 끊기지 않는다
```

| 가상 결과 (10/4) | 원본 | 수정본 |
|---|---|---|
| Ctrl+C → 설 때까지 | 4.39~5.05초 · 75~77° 더 감(궤적 끝까지) | **7번 모두 0.58~1.12초** · 그 뒤 관절 변화 최대 0.044° |
| 앞길 막힘 → 설 때까지 | 2.09초(목표까지 11° 더 가고 30° 되돌아감) | 0.28~1.08초(1번은 1.92초 · 예비 `move_stop` 불림) |

### 2단계 — 실기: Ctrl+C 즉시 정지 (10/4 오후, 박진용 구현 · 일정표 W010)
- 실기 재검증에서 처음에는 Ctrl+C가 동작이 끝난 뒤에야 들었다(증상 ④).
- 박진용이 **Ctrl+C 즉시 정지**를 구현했고, 실제 로봇에서 **움직이는 중에 Ctrl+C를 누르면 팔이 바로 서는 것**을 확인했다.

## 재발 방지
- **정지 노드 한 곳에서 판단하고 제어기에 직접 세운다(D-11).** 로봇 PC에 늘 켜 둔다. 정지 입력(화면 버튼 · 키 · 음성 '멈춰') · 로봇 차례에 웹캠이 본 사람 · 비전 신호 1초 끊김 · 로봇 알람을 모아 멈출지 정하고, 서기 궤적을 `dsr_moveit_controller`에 직접 보낸 뒤 잠근다. 집기 · 놓기는 `/d2/safety/state`의 멈춤을 보고 진행 중 목표를 취소하고(10/6 S-26, 예전 `/d2/motion/halt`), 잠금은 화면 '다시 시작'(`/d2/safety/resume`)으로만 풀린다. 다시 시작하면 항상 진행 확인부터 한다([시스템 아키텍처 설명](../시스템아키텍처_설명_v3_100713.md) 7~9번 · [IRD](../02_인터페이스_IRD_v3_100716.md)).
- **팀 규칙:** 로봇을 움직이는 코드는 Ctrl+C · 막힘 · 실패 때 먼저 로봇을 세우는 처리(서기 궤적)를 반드시 넣는다. rclpy는 `SignalHandlerOptions.NO`로 시작한다([팀 협업 규칙](../06_팀협업규칙_v1_100712.md)).
- **`move_stop`은 예비로만.** 서기 궤적 바로 뒤에 늘 부르면 가상에서 7번 중 1번 에뮬레이터가 멈췄다(joint_states 끊김). 그래서 2초 안에 안 설 때만 부른다.
- **운영:** 새 코드 첫 실행은 저속 · 펜던트를 든 짝과 함께. 사람 근처 시험 전에는 정지가 되는지부터 본다. 실물 장애물은 받침대 위 폼 블록으로만, 사람 팔로는 하지 않는다.
