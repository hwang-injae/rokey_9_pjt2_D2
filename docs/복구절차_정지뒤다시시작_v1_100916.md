# 복구 절차 — 로봇이 멈췄을 때 다시 돌리기 (W070)

> 시연 · 리허설 · 실기 중 로봇이 섰을 때 이 순서대로 한다. 근거: SDD 7.3(정지 · 실패 뒤 다시 시작) · 8.1(정지 구조), 10/7 실기에서 겪은 SAFE_OFF 복구.
> 작성 박진용(로봇 동작 · 안전 감시), 10/7. 스캔 · 복제 부분은 스캔 기능(W116) 실기 뒤 다시 확인한다.
> 10/7 저녁 IRD · SDD 5장(작업 관리자 상태)에 맞춰 시간 초과(`TIMEOUT`) · 웹 끊김(`WAIT_HMI`) · 흩뿌린 공급(`WAIT_SUPPLY` · `tilted_block`) 줄을 더했다(문서담당). 10/9: 그리퍼 응답 없음 · 피드백 없음 = 작업 관리자 `ERROR`(정지 노드 잠금 아님, E-74 · §31) · 알림 `no_match_block`(E-73) 줄을 고쳤다(PM).

## 0. 먼저 알 것

- **로봇이 서면 정지 노드가 잠근다.** 잠기면 집기 · 놓기 · 이동 명령을 모두 거절한다(결과 이유 `STOPPED`, 실행 중 멈춘 목표는 `CANCELED` — 왜 멈췄는지는 `/d2/safety/state` reason에만 있다, 10/8 E-62). 잠금은 **[다시 시작](= `/d2/safety/resume`)으로만** 풀린다.
- **로봇 알람이 남아 있으면 [다시 시작]을 해도 0.5초 안에 다시 잠긴다.** 알람(아래 표의 SAFE_OFF · SAFE_STOP · 비상정지)을 먼저 없애야 한다.
- **[다시 시작] 뒤에는 늘 '진행 확인부터'** — 작업 관리자가 관측 자세에서 놓인 블록을 다시 보고, 이미 놓인 블록은 건너뛰고 이어서 쌓는다(SDD 7.3). 관측 자세로 가는 첫 이동은 저속(`recover.speed_ratio` 0.5)이다.
- **잠기지 않고 멈추는 상태도 있다** — `WAIT_SUPPLY`(공급 채우기) · `WAIT_HMI`(웹 끊김)는 정지가 아니라 기다림이다. [다시 시작]이 아니라 화면 **[계속]**으로 이어 간다(§2 표의 '잠금 아님' 줄).
- **블록을 쥔 채 [다시 시작]하면 작업 관리자는 ERROR로 간다.** 사람이 블록을 빼고 다시 [다시 시작]한다(떨어뜨리지 않게).
- 그리퍼 명령은 잠긴 중에도 받는다 → 잠긴 상태에서 블록을 손으로 받치고 그리퍼를 열 수 있다.

## 1. 공통 순서 (어떤 이유로 멈췄든)

1. **원인을 본다** — 터미널 A에서 정지 상태와 로봇 상태를 읽는다(§3).
2. **원인을 없앤다** — §2 표대로.
3. **쥔 블록이 있으면 뺀다** — §4.
4. **사람이 작업대 밖에 있는지 본다.**
5. **[다시 시작]** — 화면 [다시 시작] 버튼, 또는 터미널 A에서 `resume`.
6. **이어서 돌린다** — 팀 흐름이면 작업 관리자가 RECOVER → 진행 확인부터 자동으로 이어 간다. 시험 도구(`run_recipe`)면 남은 블록만 다시 실행한다(§5).

## 2. 원인별로 푸는 법

| 멈춘 이유 (`/d2/safety/state` reason) | 로봇 상태 (`get_robot_state`) | 원인 없애기 | 그다음 |
|---|---|---|---|
| 화면 [정지] · 키 (`STOP_WEB` · `STOP_KEY` — 10/8 E-62) | 1 STANDBY | 멈춘 까닭 확인 | [다시 시작] |
| `run_recipe` Ctrl+C | 1 STANDBY | 없음 — 이 경로는 잠그지 않는다(목표만 취소) | `run_recipe` 다시(§5) |
| 펜던트 비상정지 (`ROBOT_ALARM:EMERGENCY_STOP`) | 6 | 비상정지 버튼을 돌려 풀기 → 펜던트에서 리셋 · 서보 ON | 상태 1 확인 → [다시 시작] |
| 충돌 감지 · 보호 정지 (`ROBOT_ALARM:SAFE_STOP`) | 5 | 부딪힌 것 치우기 → 펜던트에서 리셋 | 상태 1 확인 → [다시 시작] |
| **서보 꺼짐 (`ROBOT_ALARM:SAFE_OFF`)** | **3** | **브링업을 다시 켠다(§3-2)** — 켜질 때 드라이버가 서보를 켠다 | 상태 1 확인 → [다시 시작] |
| 그리퍼 응답 없음 · 피드백 없음 (`/d2/safety/state` reason 아님 — 집기 · 놓기 결과 `GRIPPER_NO_RESPONSE` · `NO_FEEDBACK` → 작업 관리자가 재시도 없이 `ERROR`, 정지 노드 잠금 없음, 10/9 E-74 · §31) | 1 | 그리퍼 전원 · 선 확인 → 브링업 다시 켜기. 쥔 채 멈췄으면 사람이 블록을 뺀다(그리퍼는 자동으로 안 연다) | [다시 시작] |
| 블록 놓침 · 잡기 실패 (`GRASP_FAILED` → ERROR) | 1 | 떨어진 블록 치우기, 공급 칸(흩뿌림이면 공급 영역) 블록 바로 놓기 | [다시 시작] |
| 경로 못 찾음 (`PLAN_FAILED` → ERROR) | 1 | 막는 물체 치우기(놓인 블록이 밀렸는지 확인) | [다시 시작] |
| 시간 초과 (`TIMEOUT` — `move_to` 45초 · `pick_place` 90초를 넘김) | 1 | 작업 관리자가 먼저 세우고 잠갔다(정지 요청 `source: task`). 왜 늦었는지 로그로 본다 — 경로 계획이 오래 걸림 · 제어기 응답 없음 · 막는 물체 | [다시 시작] |
| 공급이 빔 (상태 `WAIT_SUPPLY`, 알림 `supply_empty`, 잠금 아님) | 1 | 흩뿌린 공급 영역이면 테이프 안에 블록을 흩뿌려 놓기, 공급 칸 6개(대비책)면 칸 채우기 | 로봇이 관측 자세에 도착해 알림이 뜬 뒤 화면 [계속] |
| 기울어진 블록만 남음 (상태 `WAIT_SUPPLY`, 알림 `tilted_block`, 잠금 아님) | 1 | 다른 블록에 걸쳐 기울어진 블록을 바로 놓기(E-43) | 화면 [계속] |
| 맞는 블록이 없음 (상태 `WAIT_SUPPLY`, 알림 `no_match_block`, 잠금 아님 — 10/9 E-73) | 1 | 블록은 있는데 지금 놓을 블록으로 쓸 것이 없다(세우기도 안 됨) — 블록을 정리하거나 더 넣기 | 화면 [계속] |
| 웹 끊김 (상태 `WAIT_HMI`, 알림 `hmi_lost`, 잠금 아님) | 1 | 작업 관리자가 현재 블록까지 놓고 멈췄다. 웹 PC · 브로커(`mosquitto`) · 다리(`bridge`)를 다시 살린다. **끊긴 동안 화면 [정지]는 안 닿는다 — 키 · Ctrl+C · 펜던트** | 웹이 다시 붙은 뒤 화면 [계속](저절로 이어 가지 않는다) |

**SAFE_OFF가 생기는 때(10/7 실기):** 펜던트에서 안전 설정 화면에 들어가면 서보가 꺼진다(SAFE_OFF). 이때는 ROS에서 서보 켜기(`set_robot_control 3`)를 보내도 `success=True`만 오고 상태가 안 바뀐다 — 제어권이 펜던트로 넘어간 것으로 본다. **브링업을 다시 켜면** `INITIAL CONTROL_SERVO_ON` → STANDBY로 돌아온다. 실기 중에는 펜던트 안전 설정 화면에 들어가지 않는다.

## 3. 명령 (터미널별)

새 터미널은 늘 이 줄부터:
```bash
cd ~/rokey_9_pjt2_D2 && source /opt/ros/jazzy/setup.bash && source ~/cobot2_ws/install/setup.bash && source install/setup.bash
```

### 3-1. 터미널 A — 상태 보기 · 잠금 풀기
```bash
ros2 topic echo --once /d2/safety/state                                                    # stopped · locked · reason
ros2 service call /dsr_controller2/system/get_robot_state dsr_msgs2/srv/GetRobotState      # 1 STANDBY 이어야 다시 돈다
ros2 service call /d2/safety/resume std_srvs/srv/Trigger                                   # [다시 시작] — 원인을 없앤 뒤에만
```

### 3-2. 브링업 다시 켜기 (SAFE_OFF · 그리퍼 응답 없음)
- **터미널 1 (브링업)**: Ctrl+C로 끈다 → 다 꺼진 것 확인(`ps -ef | grep ros2_control_node` 가 비어야 함 — **두 개가 겹쳐 뜨면 제어기가 'already active'로 안 붙는다**) → 다시 켠다.
  ```bash
  ros2 launch d2_bringup real_moveit.launch.py mode:=real host:=192.168.1.100
  ```
  로그에 `ROBOT_STATE : STATE_STANDBY` 와 `You can start planning now!` 가 나오면 됨.
- **터미널 2 (노드 4개)**: Ctrl+C로 끄고 다시 켠다(브링업을 다시 켜면 노드도 다시 켠다).
  ```bash
  ros2 launch d2_bringup robot_nodes.launch.py mode:=real
  ```
  `[집기·놓기] 준비 끝` 이 나오면 됨. 이때 정지 노드는 새로 켜져 잠금이 없다.

런치는 **패키지 이름으로** 실행한다(`src/...` 경로로 실행하면 `__pycache__` 가 생긴다 — 10/7 `setup.py` 수정으로 빌드는 안 깨지지만 습관으로).

## 4. 블록을 쥔 채 멈췄을 때

1. 사람이 블록을 손으로 받친다(펜던트 든 사람 말고 한 사람 더).
2. **터미널 A** — 그리퍼를 연다(잠긴 중에도 받는다):
   ```bash
   ros2 service call /d2/gripper/command d2_interfaces/srv/GripperCommand "{width_m: 0.0865, force_n: 10.0}"
   ```
3. 블록을 빼서 공급 칸(흩뿌림이면 공급 영역 테이프 안)에 다시 놓는다(놓던 블록이면 작업 관리자가 진행 확인으로 '없음'을 보고 다시 집는다).
4. 그다음 [다시 시작].

## 5. 다시 이어서 돌리기

- **팀 흐름(작업 관리자 · task 노드)**: [다시 시작]만 하면 된다 — STOPPED → RECOVER → 쥔 블록 확인 → CHECK(관측 자세 저속 · 진행 확인) → 이미 놓인 블록은 건너뛰고 이어서. 조립 중이 아니었으면(스캔 중 포함) IDLE로 가니 설계를 다시 고르고 [출발].
- **시험 도구(`run_recipe`) — 터미널 B**: 진행 확인이 없으므로 **남은 순번만** 다시 준다. 예: 7번째 블록에서 멈췄고 7번이 안 놓였으면
  ```bash
  ros2 run d2_motion run_recipe --steps 7-11      # 번호 1 → y
  ```
  반쯤 놓인 블록은 사람이 치우거나 바로 놓은 뒤 실행한다.

## 6. 스캔 · 복제 중 멈췄을 때 (안 — W116 실기 뒤 확인)

- 스캔 촬영 · 추론 중(SCAN_MOVE · SCAN_CAPTURE · SCAN_INFER)에 멈추면: [다시 시작] → 작업 관리자 IDLE → **[스캔]을 처음부터 다시** 누른다(SDD 7.3 — 중간부터 잇지 않는다).
- 스캔 결과 확인 화면(SCAN_REVIEW)에서 멈추면: [다시 시작] → 작업 관리자 IDLE. 저장 전이면 다시 [스캔], 저장 뒤면 그 설계를 골라(`select_design`) [출발].
- 복제 조립 중에 멈추면: 일반 조립과 같다(§5 팀 흐름).

## 7. 하지 않는 것

- 원인을 없애기 전에 [다시 시작]을 여러 번 누르지 않는다(알람이 남아 있으면 바로 다시 잠긴다).
- 실기 중 펜던트 안전 설정 화면에 들어가지 않는다(서보가 꺼져 브링업을 다시 켜야 한다).
- 브링업을 두 개 띄우지 않는다.
- 블록을 쥔 채 그리퍼를 열지 않는다(받치는 사람 없이).
