## 1. 무엇이 문제였나
- Ctrl+C를 눌러도 로봇이 안 섰다. `pick_place_avoid.py`는 문구만 찍었다. `jenga_coop.py`는 ROS가 먼저 꺼져서 정지 명령이 안 나갔고, 오류는 삼키고 '멈춘다'고만 찍었다.
- '앞길 막힘' 때는 MoveIt 실행 취소(cancel)만 보냈다. 10/3 가상 시험에서 취소와 두산 `move_stop`만으로는 안 섰다. 제어기에 '지금 자리에 서기' 궤적(서기 궤적)을 보내야 섰다.

## 2. 바꾼 것
| 파일 | 바꾼 것 |
|---|---|
| `safe_stop.py` (새 파일) | `init_ros()`와 `SafeStop.stop()`. 정지 순서: ① 서기 궤적(`dsr_moveit_controller/follow_joint_trajectory`, 지금 관절값, 0.3초) ② MoveIt 실행 취소 ③ 설 때까지 확인. 2초 안에 안 서면 ④ 두산 `move_stop`을 부르고 2초 더 본다. 그래도 안 서면 '펜던트 비상정지!'를 크게 띄운다. 정지 중에 Ctrl+C를 또 눌러도 정지가 끊기지 않는다 |
| `pick_place_avoid.py` | `init_ros()`를 쓴다. Ctrl+C · 앞길 막힘 · 실행 실패 때 `stop()`. 원래 있던 cancel 한 줄은 뺐다. 정지에 걸린 시간을 CSV에 남긴다 |
| `jenga_coop.py` | `init_ros()`, Ctrl+C 때 `stop()`. 오류를 삼키던 `try/except`를 없앴다. 막힘 3곳(손이 아닌 것에 막힘 · 목표 근처에 손 · 갈아탈 수 없음)은 서기 궤적을 보낸 뒤 설 때까지 기다린다 |
| `demo_move.py` · `demo2_route.py` | `init_ros()`, Ctrl+C 때 `stop()` (가상용이지만 실기에서도 돌 수 있어서) |
| `r01_box.py` (새 시험 도구) | 실기 '막힘' 시험용. MoveIt 장면에 가상 상자를 넣고 뺀다(실물은 안 둔다) |

- 손이 다가오면 멈추고 바로 비키는 동작(`jenga_coop.py`)은 그대로 두었다. 비키기가 바로 이어져야 해서 기다리지 않는다.
- `move_stop`은 **안 설 때만** 쓴다. 서기 궤적 바로 뒤에 `move_stop`을 7번 불렀더니 1번 에뮬레이터가 멈춰(joint_states 끊김) 브링업을 다시 켰다.

## 3. 시험 조건
- 시작 자세 관절 0°에서 홈 `[0, 0, 90, 0, 90, 0]`으로 가는 중에 Ctrl+C(SIGINT)를 보냈다. 속도는 기본값(`pick_place` 0.1 · `jenga_coop` 0.15).
- 정지는 따로 띄운 기록 노드가 `/joint_states`로 쟀다. '섰다' = 관절 변화가 0.05° 이하로 계속 머문 첫 시각.
- 이 PC에서는 박진용 launch의 모델 파일에 ros2_control이 없어, 시험할 때만 같은 패키지의 다른 모델 파일로 바꾼 복사본을 썼다(손가락 끝 `rg2_tcp`는 같다).

## 5. 가상이라서 생긴 것
- 가상에서는 로봇이 움직이는 동안 joint_states가 0.25~0.9초 간격으로만 왔다(멈춰 있을 때는 초당 75~80번).
- 그래서 '서기 자리'가 0.1~0.5초 전 자리가 된다. 로봇은 Ctrl+C 뒤 조금 더 간 다음 그 자리로 4~9° 되돌아가서 선다. 위 '완전히 설 때까지' 시간에는 되돌아간 시간이 들어 있다.
- `jenga_coop` '목표 근처'의 17°도 원본에서 비슷하게 나와(11° 더 감 · 30° 되돌아감) 고친 코드보다 에뮬레이터 탓으로 본다(추정). 실기에서 joint_states가 촘촘하면 되돌아감이 작을 것이다(추정, 확인 필요).

## 6. 실기 첫 시험 순서 (10/4 [로봇 1], 박진용)
1. 펜던트를 든 사람 1명이 엄지를 비상정지 버튼에 두고 로봇만 본다. 다른 사람은 작업대 밖.
2. 속도는 `--scale 0.1`(기본값)만 쓴다. `ros2 bag record /joint_states`를 켜 정지 시간 · 거리를 잰다.
3. 실행하면 '[정지 준비] 서기 궤적 컨트롤러: 있음'과 '두산 move_stop 서비스' 두 줄이 나와야 한다. 안 나오면 실기를 하지 않는다.
4. **장애물 없이 Ctrl+C 먼저 3번** — 움직이기 시작하고 1~2초 뒤 Ctrl+C. 1초가 지나도 움직이면 펜던트 비상정지(프로그램의 `move_stop`을 기다리지 않는다).
5. **그다음 막힘** — 실물이 아니라 `r01_box.py`로 가상 상자를 넣고 뺀다. 실물 장애물은 받침대 위 폼 블록으로만 한다. 사람 팔로는 하지 않는다.
6. `jenga_coop`은 가상에서 가짜 손으로 먼저 돌린 뒤, 4 · 5번이 통과하면 실기.
7. CSV의 'Ctrl+C 정지 섰다 x s' · '정지 확인 x s'와 bag 파일을 같이 기록한다.

## 7. 아직 확인 못 한 것 (10/4 오전 작성 때 기준)
- **실기 동작 전부.** 실기는 `servoj_rt`로 움직인다(가상은 `amovej`). 서기 궤적이 실기에서도 듣는지, 정지 시간 · 거리는 모른다. → Ctrl+C 즉시 정지는 10/4 오후 실기에서 확인됨(위 '실기 확인'). 정지 시간 · 거리 수치는 아직 없다.
- 예비 `move_stop`이 실기에서 듣는지, 그 뒤 다음 실행이 정상인지.
- 서기 궤적이 실기에서 안 들으면 2초 뒤에야 `move_stop`을 부른다. 그 2초 동안은 사람이 펜던트로 먼저 세워야 한다. 실기 결과를 보고 첫 대기 시간(2.0초)을 줄인다.
- 실기 joint_states 간격(가상처럼 띄엄띄엄 오면 되돌아감이 생기고 정지 확인이 늦어진다).
- `jenga_coop`의 '갈아탈 수 없어 멈춤'은 가상에서 일으키지 못했다(같은 `stop()`을 쓴다). `demo2_route.py` Ctrl+C는 따로 돌려 보지 않았다.

**실기 결과:** 10/4 오후 실기 확인 완료(W010, 박진용) — MoveIt2 동작 정상, Ctrl+C 즉시 정지를 구현해 팔이 바로 섬. 정지 시간 수치 ＿＿ · 코드는 PR 예정. 정지 → 재개 · 보호 정지 해제 · 충돌 감지(R-02)는 10/7 오전(W059).
