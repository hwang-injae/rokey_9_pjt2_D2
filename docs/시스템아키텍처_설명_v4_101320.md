## 1. 먼저 범례(그림 맨 위)

- **① 화살표 색 = 데이터 갈래 7개:** 파랑 **명령**(화면 버튼 · 마이크 → 작업 관리자 · 음성) · 보라 **표시**(작업 관리자 · 정지 · 그리퍼 상태 → 화면) · **주황 설계**(AI 생성(Claude) · 검사 `check_design` · 설계 꺼내기 `get_design` · 저장) · 초록 **관측 · 스캔 · 진행표**(배치 확인 · 흩어진 블록 찾기 · 스캔 · 손목 영상 · 점군) · 검정 **동작** · 빨강 **정지** · 회색 **장치 · 바깥 · 연결 신호**(USB · 제어기 · 드라이버 · Claude · Whisper · `alive`).
- **② 선 모양:** 실선 = 지금 main에 있는 연결. **점선 = 예정**(정했지만 main에 없음 — voice.py · 음성 '멈춰' · PostgreSQL · 작업 관리자가 [초기화] · [그리퍼 열기] 명령 받기(W183)). 다리(반원) = 선이 겹치는 곳(이어진 것 아님).
- **③ 상자 종류:** 노드 카드(머리띠 색 = 파트: 주황 HMI · 초록 비전 · 파랑 로봇 동작) · 이미 있는 노드(브링업 · 카메라 드라이버 — 설치해서 씀) · **예정(노란 점선 상자 · 입출력)** · 저장소(JSON 파일 · MQTT 브로커) · 라이브러리(레시피 도구) · 개발 도구 · 장치 · 컨테이너(파란 점선 큰 상자: `web` · `mosquitto`, 예정 `db`) · 클래스(카드 안 회색 묶음).
- **④ 낱말:** 노드 · 패키지 · 클래스 · 컨테이너 · MQTT · 다리 · 부품 JSON · 레시피 · 토픽 · 서비스 · 액션(2장).
- **그림에서 `MQTT …`로 시작하는 입력 · 출력**은 웹 PC ↔ 로봇 PC 사이를 오가는 것이다. 화살표는 논리 연결로 그렸지만 **실제로는 전부 웹 PC의 브로커(`mosquitto`)를 거친다.** 서비스 · 액션 · HTTP 화살표는 부탁하는 방향으로만 그렸다(답은 같은 길로 돌아온다).

## 3. 큰 그림 — 가로 띠 3개

위 **웹 PC = 한석형 PC** 띠(ROS 없음 — 컨테이너 2개 + 호스트 `claude_bridge` · 예정 `voice.py`) → 가운데 **로봇 PC = 박진용 PC** 띠(ROS 노드 전부, 호스트) → 아래 **장치 · 바깥 서비스** 띠(사람 · 카메라 · Claude · Whisper · 마이크 · 제어기 · 그리퍼). PC 배치는 10/11 E-92.

- **두 PC 사이를 잇는 것은 다리 노드 하나**다. 웹 → 로봇: 명령 · 검사 · 정지 · 다시 시작(`…/req`) + 음성 문장(`d2/hmi/intent`) + 웹 연결 신호(`d2/web/alive`). 로봇 → 웹: 상태 토픽 5개(retained) + 설계 꺼내기 · 조립 기록 요청 + 다리 연결 신호(`d2/bridge/alive`) + 바이트(손목 검출 영상 · 스캔 사진 · 점군).
- **생성 · 저장은 웹 PC 안에서, 검사는 로봇 PC(task)에서** 끝난다.
- 웹 PC 안에서는 브라우저의 `frontend`가 `backend`와 **REST · WebSocket `/ws`로만** 주고받는다(E-41). 화면은 웹 PC에서만 연다(`127.0.0.1:8000`).
- **설계 AI = Claude**(10/13 E-99): backend가 OpenAI 형식 요청을 호스트의 `claude_bridge`(:8790)로 보내면, 웹 PC에 로그인된 Claude Code(`claude -p`)가 답한다. 키가 없다. OpenAI는 음성 STT(Whisper)에만 남는다.

## 4. 카드 하나를 읽는 법

왼쪽 **입력**(받는 것) → 가운데 **처리**(번호 순, 클래스 묶음) → 오른쪽 **출력**(내보내는 것). 카드 안 가는 선은 어느 입력이 어느 처리로 가고, 어느 처리가 어느 출력을 내는지다(색 = 들어온 화살표 색). 노란 점선 입출력은 예정이다. 예: **task 카드** — 입력 `/d2/task/check_design(서비스 받음)`은 ⑪ 검사 1 ~ 20번 → ⑫ 21번 · 변환기 ① → 출력 `check_design 답`.

## 5. 흐름 따라가기 — 1번부터 17번

번호 · 순서는 v3와 같다. **화면 ↔ 로봇 PC 노드 사이에는 늘 "frontend → REST → backend → MQTT → bridge →"가 낀다.**

## 6. 자주 묻는 것

- **왜 PC 사이를 ROS 2가 아니라 MQTT로?** 웹 PC에 ROS · 두산 환경을 깔지 않아도 되고, DDS 멀티캐스트 문제가 없고, `mosquitto_sub -t 'd2/#' -v` 한 줄로 PC 사이 메시지를 다 볼 수 있다(E-27). 로봇 PC 안은 ROS 2(CycloneDDS · `ROS_DOMAIN_ID` 60).
- **MQTT에는 서비스가 없는데?** `…/req` · `…/res`를 짝으로 두고 `req_id`로 맞춘다. 5초 안에 답이 없으면 `TIMEOUT`(IRD 10장).
- **설계 AI가 왜 컨테이너 밖에 있나?** Claude는 웹 PC에 로그인된 Claude Code로 부르기 때문이다(키 없음 · 구독 한도). backend는 OpenAI 라이브러리 그대로 주소(`D2_LLM_URL`)만 `claude_bridge`로 돌린다. 준비는 `python3 web/claude_bridge.py --check`로 본다.
- **브로커 · 다리가 죽으면?** 화면만 끊긴다. 로봇 PC의 정지(키 · Ctrl+C · 알람 · 펜던트)는 그대로이고, 화면은 `d2/bridge/alive`가 3초 끊기면 "연결 끊김"을 띄우고 [조립] · [스캔]을 막는다. 조립 중 웹이 3초 끊기면 task는 지금 부품까지 놓고 `WAIT_HMI`로 멈춘다(정지 아님) → 다시 붙고 [계속].
- **AI가 만든 설계가 이상하면?** 검사 묶음(③④ — 21번 Template 검사 포함)이 거르고, 통과해도 사람이 3D를 보고 [조립]을 눌러야 로봇이 움직인다(SR-09). 생성 직후 자동 출발은 없다.
- **DB는 어디서 읽나?** backend(DesignStore) 한 곳. task · 손목 비전은 `get_design` · `save_build`(다리 제공)로만, 화면은 REST로만. 지금은 JSON 파일 폴더 `/data`, PostgreSQL은 W088(예정).
- **음성으로 출발할 수 있나?** 화면 흐름에서는 아니다(E-96). 음성은 요청 글만 넣는다. task가 `/d2/hmi/intent`의 `select_design` · `start` · `cancel`을 받는 코드는 남아 있지만 voice.py가 보내는 것은 `request_design`뿐이고, task는 그것을 무시한다.
- **인터넷이 끊기면?** AI 생성 · 스캔 [그대로 저장](AI 채우기) · 음성이 안 된다. 저장된 설계 조립(⑥ ~ ⑪)과 **스캔 추천 설계 [조립]**은 된다.
