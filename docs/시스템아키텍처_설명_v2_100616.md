## 1. 먼저 범례(그림 맨 위)

- **① 화살표 색 = 데이터 갈래 7개:** 파랑 **명령**(화면 · 음성 → 작업 관리자) · 보라 **표시**(작업 관리자 · 그리퍼 → 화면) · **주황 설계**(생성 · 검사 `check_design` · 설계 꺼내기 `get_design` · 저장 — 블록 JSON · 레시피가 오가는 길, **새로**) · 초록 **관측 · 스캔 · 진행표** · 검정 **동작** · 빨강 **정지** · 회색 **장치 · 바깥**(USB · 제어기 · OpenAI).
- **② 선 모양:** 실선 = 1차 · 핵심(10/13 동결까지). 점선 = 챌린지에 붙일 연결(카메라 끊김 → 정지, 음성 '멈춰'). 다리(반원) = 선이 겹치는 곳.
- **③ 상자 종류:** 노드 카드(머리띠 색 = 파트: 주황 HMI · 초록 비전 · 파랑 로봇 동작) · 이미 있는 노드(브링업) · 챌린지 노드(점선) · **저장소(DB) · 라이브러리(레시피 도구)** · 장치 · 컨테이너(파란 점선 큰 상자: `hmi` · `db-hmi`) · 클래스(카드 안 회색 묶음).
- **④ 낱말:** 노드 · 패키지 · 클래스 · 컨테이너 · **블록 JSON · 레시피** · 토픽 · 서비스 · 액션.

## 3. 큰 그림 — 가로 띠 3개

위 **운영 PC** 띠(컨테이너 2개 + 호스트) → 가운데 **로봇 PC** 띠(호스트) → 아래 **장치 · 바깥 서비스** 띠(사람 · OpenAI · 마이크 · 카메라 · 제어기 · 그리퍼). 운영 PC → 로봇 PC로 가는 명령은 다섯 갈래뿐이다: 정지, 이동(`move_to`), 진행 확인(`check_progress`), 스캔(`scan_capture` · `scan_infer`), 블록 1개(`pick_place`). **생성 · 검사 · 저장은 운영 PC 안에서 끝난다.**

## 4. 카드 하나를 읽는 법 — v2와 같음

왼쪽 **입력**(받는 것) → 가운데 **처리**(번호 순, 클래스 묶음) → 오른쪽 **출력**(내보내는 것). 카드 안 가는 선은 어느 입력이 어느 처리로 가고, 어느 처리가 어느 출력을 내는지다(색 = 들어온 화살표 색). 예: **task 카드** — 입력 `check_design(받음)`은 ⑨ 검사 → ⑩ 변환기 ① → 출력 `check_design 답`. 입력 `scan_infer 답`은 ⑤ 스캔 상태 → 출력 `scan_result`.

## 6. 자주 묻는 것

- **AI가 만든 설계가 이상하면?** 검사 묶음(③④)이 거르고, 통과해도 사람이 미리보기를 보고 [출발]을 눌러야 로봇이 움직인다(SR-09). 생성 직후 자동 출발은 없다.
- **로봇 쪽 노드가 바뀌었나?** pick_place · scene_manager · gripper · safety_stop은 v2와 같다(+ move_to 촬영 자세 2개, 서기 궤적 토픽). 조립 엔진은 레시피만 안다 — 설계가 CAD에서 왔든 AI · 스캔에서 왔든 같다.
- **왜 검사는 HMI가 아니라 task에?** 쌓을 만한지는 로봇 쪽(작업 판단)이 가장 잘 알고, 변환기 ①(레시피 도구)을 바로 부를 수 있어서. HMI 컨테이너 ↔ 호스트 task 사이는 서비스 한 번(`check_design`)이다.
- **DB는 어디서 읽나?** web_ui(DesignStore) 한 곳. task는 `get_design` · `save_build` 서비스로만. 제품이 정해지기 전에는 JSON 파일 폴더로 돈다.
- **사람 감지는?** 웹캠을 빼서 없다(E-19). [출발] · [스캔] · [계속]을 누르는 사람이 영역 밖인지 확인한다. 카메라 신호 끊김 → 정지는 챌린지(점선).
- **공급 칸이 비면?** `SLOT_EMPTY`가 모든 칸 → task WAIT_SUPPLY → 화면 "공급 채워 주세요" → 사람이 채우고 [계속] 버튼(= `start`).
- **인터넷이 끊기면?** 생성 · 음성 분류가 안 된다. 저장된 설계 조립(⑥~⑪)은 된다.

## 8. 그림이 IRD와 다른 곳 · 아직 '안'인 것

- 그림의 새 이름(`JsonQuery` · `check_design` · `get_design` · `save_build` · `scan_capture` · `scan_infer` · `scan_result` · `scan` 명령 · `request_design` 의도 · 촬영 자세 2개)은 IRD v2에 **'안'** 으로 들어 있고 **10/7 오전 W121**에서 확정한다. 확정 전에는 IRD v2 이름을 그대로 쓴다.
- `save_build`(task → web_ui, 조립 결과를 DB로)는 IRD 12장의 안 ⓐ다. ⓑ(HMI가 state · progress를 구독해 스스로 기록)로 정하면 이 화살표가 없어지고 보라 표시 선만 남는다.
- 레시피 도구의 패키지 이름 · 위치는 로봇 동작(한세교)이 정한다. 그림은 '라이브러리' 상자로만 그렸다.
- 스캔 사진을 화면에 보내는 방법(공유 폴더 vs 전송)은 미정 — 그림은 경로를 `scan_result`에 싣는 것으로 그렸다.

## 9. 점선 — 챌린지에 붙일 것

- `wrist_block` 카메라 연결 신호 → `safety_stop`(1초 끊기면 `VISION_LOST`로 정지).
- `voice_stop`(음성 '멈춰', PC 안 키워드) → `safety_stop`.
- 그림에 없는 챌린지: 스캔 설계 요청대로 고치기(①, web_ui DesignGenerator가 스캔 설계를 바탕으로) · 흩어진 블록(②) · 협동 번갈아 쌓기(③ — 옛 v2의 10~11번 흐름).
