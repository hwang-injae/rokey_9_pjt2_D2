## 1. 먼저 범례(그림 맨 위)

- **① 화살표 색 = 데이터 갈래 7개:** 파랑 **명령**(화면 · 음성 → 다리 → 작업 관리자) · 보라 **표시**(작업 관리자 · 그리퍼 → 다리 → 화면) · **주황 설계**(생성 · 검사 `check_design` · 설계 꺼내기 `get_design` · 저장 — 블록 JSON · 레시피가 오가는 길) · 초록 **관측 · 스캔 · 진행표** · 검정 **동작** · 빨강 **정지** · 회색 **장치 · 바깥 · 생존 신호**(USB · 제어기 · OpenAI · `alive`).
- **② 선 모양:** 실선 = 1차 · 핵심(10/13 동결까지). 점선 = 나중에 붙일 연결(카메라 끊김 → 정지, 음성 '멈춰' — 챌린지 아님, PL 10/6 19시). 다리(반원) = 선이 겹치는 곳.
- **③ 상자 종류:** 노드 카드(머리띠 색 = 파트: 주황 HMI · 초록 비전 · 파랑 로봇 동작) · 이미 있는 노드(브링업) · 나중에 붙일 노드(점선) · **저장소(DB · MQTT 브로커) · 라이브러리(레시피 도구)** · 장치 · 컨테이너(파란 점선 큰 상자: `web` · `mosquitto` · `db` — 모두 웹 PC. `web` 상자 안에 `frontend` · `backend` 카드 둘) · 클래스(카드 안 회색 묶음).
- **④ 낱말:** 노드 · 패키지 · 클래스 · 컨테이너 · **MQTT · 다리** · 블록 JSON · 레시피 · 토픽 · 서비스 · 액션.
- **그림에서 `MQTT …`로 시작하는 입력 · 출력**은 웹 PC ↔ 로봇 PC 사이를 오가는 것이다. 화살표는 논리 연결로 그렸지만 **실제로는 전부 웹 PC의 브로커(`mosquitto`)를 거친다.**

## 3. 큰 그림 — 가로 띠 3개

위 **웹 PC** 띠(ROS 없음 — 컨테이너 3개 + 호스트 음성) → 가운데 **로봇 PC** 띠(ROS 노드 전부, 호스트) → 아래 **장치 · 바깥 서비스** 띠(사람 · OpenAI · 마이크 · 카메라 · 제어기 · 그리퍼). **두 PC 사이를 잇는 것은 다리 노드 하나**다. 웹 PC → 로봇 PC로 가는 것은 다섯 갈래(명령 · 의도 · 검사 · 정지 · 다시 시작) + 웹 생존 신호(`d2/web/alive`), 로봇 PC → 웹 PC는 상태 토픽 5개 + 설계 꺼내기 · 조립 기록 요청 + 다리 생존 신호(`d2/bridge/alive`) + 사진 · 점군 · 손목 검출 영상(바이너리 — 10/8 E-67). **생성 · 저장은 웹 PC 안에서, 검사는 로봇 PC(task)에서 끝난다.** 웹 PC 안에서는 브라우저의 `frontend`가 `backend`와 **REST(`/api/designs` · `/api/robot`) · WebSocket `/ws`로만** 주고받고, MQTT · OpenAI · DB는 `backend`(와 음성 `voice`)만 쓴다(E-41).

## 4. 카드 하나를 읽는 법 — v2와 같음

왼쪽 **입력**(받는 것) → 가운데 **처리**(번호 순, 클래스 묶음) → 오른쪽 **출력**(내보내는 것). 카드 안 가는 선은 어느 입력이 어느 처리로 가고, 어느 처리가 어느 출력을 내는지다(색 = 들어온 화살표 색). 예: **bridge 카드** — 입력 `MQTT …/req`는 ① ROS 서비스 호출 → 출력 `/d2/hmi/command · …(서비스 부름)`과 `MQTT …/res`. 입력 `/d2/task/state · …(토픽)`은 ④ → 출력 `MQTT d2/task/state · …(retained)`.

## 5. 흐름 따라가기 — 1번부터 17번

번호 · 순서는 v2와 같다. 달라진 것은 **화면 · 음성 ↔ 작업 관리자 · 정지 노드 사이에 "→ MQTT → bridge →"가 끼는 것**, 그리고 웹 PC 안에서 **화면(frontend) → REST → backend, backend → WebSocket `/ws` → 화면**이 한 번 더 끼는 것(v6)이다.

## 6. 자주 묻는 것

- **왜 PC 사이를 ROS 2가 아니라 MQTT로?** 웹 PC에 ROS · 두산 환경을 깔지 않아도 되고, 강의실 망의 DDS 멀티캐스트 문제가 없고, `mosquitto_sub -t 'd2/#' -v` 한 줄로 PC 사이 모든 메시지를 볼 수 있다(E-27). 로봇 PC 안은 그대로 ROS 2다.
- **MQTT에는 서비스가 없는데 명령 · 검사 · 설계 꺼내기는?** 요청 토픽 `…/req`와 응답 토픽 `…/res`를 짝으로 두고 `req_id`로 맞춘다. 5초 안에 답이 없으면 `TIMEOUT`(E-29, IRD 10장).
- **ROS 쪽 코드가 바뀌나?** 안 바뀐다(E-28). task · 비전 · 로봇 동작은 `/d2/hmi/…` 이름을 그대로 쓰고, 그 자리에 다리가 선다. 가짜 노드 `mock_web_ui`는 이름만 `mock_bridge`로.
- **브로커 · 다리가 죽으면?** 화면만 끊긴다. 로봇 PC의 정지(키 · Ctrl+C · 알람 · 펜던트)는 그대로이고, 화면은 `d2/bridge/alive`가 끊기면 "연결 끊김"을 크게 띄운다. 조립 중 웹이 3초 끊기면(`d2/web/alive` → 다리 → `/d2/hmi/alive`) task는 현재 블록까지 놓고 **`WAIT_HMI`**(알림 `hmi_lost`)로 멈춘다 — 정지(서기 궤적)는 아니고, 웹이 다시 붙고 사람이 [계속](= `start`)을 눌러야 진행 확인부터 이어 간다(10/7 PL).
- **AI가 만든 설계가 이상하면?** 검사 묶음(③④)이 거르고, 통과해도 사람이 미리보기를 보고 [출발]을 눌러야 로봇이 움직인다(SR-09). 생성 직후 자동 출발은 없다.
- **왜 검사는 backend가 아니라 task에?** 쌓을 만한지는 로봇 쪽(작업 판단)이 가장 잘 알고, 변환기 ①(`d2_task` 안, E-58)을 바로 부를 수 있어서. 웹 PC ↔ 로봇 PC 사이는 요청 한 번(`check_design/req` → `…/res`)이다.
- **DB는 어디서 읽나?** backend(DesignStore) 한 곳. task는 `get_design` · `save_build` 서비스(다리 제공)로만, 화면(frontend)은 REST로만. W088 전에는 JSON 파일 폴더로 돈다.
- **frontend · backend는 카드가 둘인데 컨테이너는 왜 하나?** frontend는 Next.js가 미리 만든 정적 파일(`out/`)이라 backend(FastAPI :8000)가 그대로 내려 주고, 실제로는 사람의 브라우저에서 돈다. 웹 PC에서 도는 프로세스는 backend 하나다(실행 시 Node 없음, E-41).
- **사람 감지는?** 웹캠을 빼서 없다(E-19). [출발] · [스캔] · [계속]을 누르는 사람이 영역 밖인지 확인한다. 카메라 신호 끊김 → 정지는 나중에(점선).
- **공급이 비면?** 핵심은 흩뿌린 공급 영역(E-36): 공급 영역 관측 자세에서 손목 카메라(`find_blocks`)에 블록이 하나도 없으면 WAIT_SUPPLY → 화면 "공급 채워 주세요" → 사람이 블록을 놓고 [계속] 버튼(= `start`) → 다시 보고 고른다. 기울어진 블록(과 그것이 걸친 블록)만 남으면 같은 WAIT_SUPPLY + 알림 `tilted_block` → 사람이 바로 놓고 [계속] — E-43. 공급 칸 6개(대비책 — 흩어진 집기가 10/12 저녁까지 안 되면 되돌림)는 `SLOT_EMPTY`로 맞는 칸이 다 비면 WAIT_SUPPLY → 채우고 [계속] → 같은 블록부터.
- **인터넷이 끊기면?** 생성 · 음성(Whisper STT · 분류)이 안 된다. 저장된 설계 조립(⑥~⑪)은 된다.

## 8. 그림이 IRD와 다른 곳 · 아직 '안'인 것

- 그림의 새 이름(`JsonQuery` · `check_design` · `get_design` · `save_build` · `scan_capture` · `scan_infer` · `scan_result` · `find_blocks` · `/d2/hmi/alive` · `scan` · `cancel` 명령 · `request_design` 의도 · 촬영 자세 2개 · `observe_supply` · `WAIT_HMI`)과 **MQTT 토픽 규칙 · `req_id` · 생존 신호 · `mqtt.*` 키**는 IRD v3에 **10/7 13시 W121에서 '정함'** 으로 들어갔고 **10/8 '정함'**(E-57)이 됐다. 그림과 다르면 IRD 이름을 쓴다.
- **다리 노드 담당 = 황인재**(10/7 21시 PL, E-56 — 양 끝을 한 사람이). 그림은 HMI 머리띠로 그렸다.
- `save_build`(task → 다리 → backend, 조립 결과를 DB로)는 IRD 12장 안 ⓐ로 **정함**(W121 — `build/1`, 응답 `ok` = DB에 저장됨, 같은 `run_id`는 한 번만 저장). 그림에 '(안)'이 남아 있으면 IRD를 따른다.
- 레시피 도구(CAD → 레시피)는 `src/recipe_manager`(한세교, ROS 패키지 아님 — PR #51로 정리, 사람이 돌림). **변환기 ①(블록 JSON → 레시피)은 `d2_task` 안 별도 파일**(10/8 PL, E-58 — 담당 한세교)로 task(DesignChecker)가 import 한다. 그림은 task 카드 ⑫(변환기 ①)와 '라이브러리' 상자(레시피 도구)로 그렸다.
- 레시피 파일 2개(`<모델ID>_recipe.json` `recipe/2.0` + `_placements.csv` — E-52 두 파일 → 10/8 E-69)로 **옮겼다** — 10/8 밤 한세교 새 4종 + 레시피 도구 저장 부분(#93)과 읽는 쪽 3명(W141 #92 · W138 #94 · W140 #95)이 함께 merge. 저장소의 레시피 4종(`src/d2_robot/d2_bringup/recipes/` · `src/recipe_manager/recipes/`)은 이 두 파일이다. 옛 형식(E-52 `cad_*/1.0` · `assembly.recipe/1.0`)은 `schema`를 보고 거절한다. 변환기 ①(블록 JSON → 레시피)은 **계산 값만** 채우고, 역할 · 순서 · 잡기는 AI 칸 그대로 — 본체 · task 연결은 W110(10/8 밤 끝 — #99 본체 · #100 검사 묶음 연결).
- 세우기 동작(E-37 — 눕힌 블록을 세워 공급 영역의 **지정 빈 자리**(W146, 10/8 E-65)에 다시 놓고 집음, 실기 W131)은 그림에 따로 그리지 않았다. 표현(`pick_place`에 칸 추가 안)은 아직 '안'이다(IRD 12장).
- 스캔 사진 · 점군 · 손목 검출 영상은 **다리가 MQTT 바이너리 토픽으로** 보낸다 — 정함(10/8 E-67, IRD 10.5): `d2/vision/scan_image`(JPEG ≤ 500 KB) · `d2/vision/scan_cloud`(PLY, `base_link` · 복셀 3 mm · ≤ 2 MB — `scan_result`의 `cloud_path`, 없으면 점군 창만 안 띄움) · `d2/vision/wrist_image`(검출 결과를 그린 JPEG 640×480 · 약 65 KB · 1~2 Hz). 그림에는 `wrist_image` 화살표가 없다.
- **그림에 남은 옛 글(10/8 E-60 · E-67 · E-69 전 — 이 글 · IRD를 따른다):** 범례 '블록 JSON · 레시피'(`_structure.json` `cad_structure/1.0` + `_recipe.json` `cad_recipe/1.0`) · 레시피 도구 상자(`_structure.json` · `cad_*/1.0`) · DesignGenerator '2단계 생성' · backend ④ '튜닝(템플릿 · 숫자) → 자유 생성' · `check_design` · `get_design` 답의 '구조 · 레시피'(지금은 `recipe` · `placements`) · backend ⑤ '통과면 저장'(지금은 후보 3개 중 사람이 고른 1개) · bridge ⑤ '사진 · 점군 바이너리(안)'(지금은 정함) · `scan_infer` 답에 `cloud_path` 없음 · `check_progress`에 `run_id` 없음. 그림을 고칠 때 같이 고친다.
- 그림의 MQTT 화살표는 backend ↔ bridge를 직접 잇는 것처럼 그렸지만 모두 `mosquitto`를 거친다. 브로커 상자에 화살표를 따로 긋지 않았다.
- 3D 미리보기를 어느 페이지에 둘지는 미정(E-35 — 프런트 설계 뒤). `Preview3D` 컴포넌트 하나라 어느 페이지에도 붙인다.
