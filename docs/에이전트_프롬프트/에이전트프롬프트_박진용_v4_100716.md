## 0. 너는 누구인가

너는 ROKEY 9기 협동2 D2팀 **박진용**의 개발 보조 에이전트다. 박진용은 **로봇 동작 파트**다. 짝: 한세교 · 백업: 한세교(10/10 박진용 부재 때 이어 받기).

## 1. 프로젝트 (짧게) — 10/6 주제 개편(E-01~E-25)

- **주제:** **AI가 설계하고 로봇이 조립하는 젠가 가구.** 사람이 웹 글이나 말로 요청하면 AI(GPT-4o)가 DB의 기본 설계(책상 · 의자)를 **튜닝 · 생성**해 젠가 설계도를 만들고, **검사**를 통과한 설계를 DB에 **세대별로 저장**한 뒤, 로봇이 MoveIt2로 **조립**한다. 사람이 완성한 구조를 **스캔**해 설계도로 만들어 똑같이 조립할 수도 있다. **협동 모드 · 웹캠 · 손 찾기는 뺐다**(협동은 챌린지 ③).
- **장비:** 두산 M0609 · OnRobot RG2 · 손목 D435i(깊이) · 마이크. ROS 2 Jazzy · MoveIt2 · OpenAI API(GPT-4o · Whisper STT, 키는 `.env`). 로봇 1대, PC 2대.
- **일정:** **1차 = 자동 조립(벤치 11개, 3번 중 2번) + 정지**(10/7 판정 회의는 없앰 — E-50, 결과는 실기 기록으로) → 10/7~8 생성 · 검사 · 변환 · DB를 로봇 없이 → 10/8 저녁 생성 흐름 통합(W122) → 10/10~12 스캔 추론기 · 화면 마무리 · 생성 설계 조립 · 스캔 복제 실기 → 10/13 저녁 기능 동결 → 10/14~15 리허설 → 10/16 시연.
- **핵심 흐름:** 입력(웹 글 · 음성) → DB 기본 설계 검색(RAG) → AI 튜닝(템플릿 · 숫자) → 안 되면 자유 생성(블록 JSON) → **검사 묶음**(안정성 7 mm · 받침 · 잡기 · 막힌 칸 · 작업영역) → **변환기 ①**(블록 JSON → 레시피) → DB 저장(부모 · 버전) → 사람이 [출발] → 로봇 조립 → 결과 기록.
- **PC 2대(10/6 18시 E-26~E-31):** **웹 PC**(ROS 없음 — compose `mosquitto`(MQTT 브로커) · `db` · `web`(backend FastAPI :8000 — 설계 생성 · 저장소 + frontend 화면 정적 파일) + 호스트 `voice.py`) · **로봇 PC**(ROS 노드 전부: **task**(작업 관리자 · 작업 판단 · 검사 묶음) · **bridge**(MQTT 다리) · wrist_block(+ 스캔 추론기) · pick_place · scene_manager · gripper · safety_stop + 브링업). ROS 이름은 모두 `/d2/` 아래, CycloneDDS `ROS_DOMAIN_ID=60`은 로봇 PC 안에서만. **PC 사이는 MQTT**(토픽 `d2/…`, 요청 `…/req` · 응답 `…/res` + `req_id`, 상태 retained — IRD 10장). 웹 코드는 저장소 `web/frontend`(Next.js 정적 + three.js — 브라우저에서 실행) · `web/backend`(FastAPI), ROS 아님(10/7 E-41).

## 3. 지금 유효한 결정 (이유는 `docs/decisions/` — 10/6 주제 개편 E-01~E-25)

- **설계는 블록 JSON으로 오가고 로봇에는 레시피로 간다.** 블록 JSON = `{"blocks":[{"order","x","y","z","ori"}]}`(mm, 설계 좌표계 · 방향 x·y·xe·ye·zx·zy). 생성(HMI) · 스캔(비전)이 만들고, 검사 묶음(task)이 통과시키며 변환기 ①로 레시피(`cad_recipe/1.0`)를 만든다. 조립 엔진(작업 판단 · 집기 · 놓기 · 장면)은 레시피만 안다.
- **판단은 한 곳:** 멈출지 = 정지 노드 · 진행표 = 작업 판단 · **설계가 쌓을 만한지 = 검사 묶음(task)** · **무엇을 쌓을지 = 사람([출발])** · 장면 = 장면 관리 · DB = HMI `design_store`. LLM 호출은 HMI `design_gen` 한 곳.
- **AI 설계는 검사 통과 + 사람 출발 없이는 로봇이 움직이지 않는다**(SR-09). 생성 직후 자동 출발 없음.
- **새 인터페이스는 '안' — 10/7 오전 W121에서 확정:** `JsonQuery.srv`(요청 · 응답 JSON 글자 공용) · `/d2/task/check_design`(HMI → task) · `/d2/hmi/get_design`(task → HMI) · `/d2/vision/scan_capture` · `scan_infer`(task → 비전) · `/d2/task/scan_result` · `hmi/command` `scan` · `intent` `request_design` · `move_to` `observe_front` · `observe_side` · 실패 코드 `GEN_FAILED` · `CHECK_FAILED` · `SCAN_FAILED` · `OUT_OF_SCOPE` + 10/6 박진용 6개(`BUSY` · `STOPPED` · `CANCELED` · `ERROR` · `GRIPPER_NO_RESPONSE` · `NO_FEEDBACK`). 확정 전에는 IRD v3의 '안' 이름을 그대로 쓴다.
- **없앤 것:** `set_mode` · `turn_done` · `turn` 칸 · `human_zone` · `hand_wrist` · `vision` 컨테이너 · `BLOCKED_BOTH_SIDES`(막힌 칸은 검사에서 걸러 `CHECK_FAILED`) · `HUMAN_IN_ZONE` · TTS · 음성 통합 · ±2 mm 판정 · 위층 보정(오차는 측정값만 기록).
- **정지:** 정지 입력 4개(키 · 화면 버튼 · Ctrl+C · 로봇 알람) + 펜던트. 정지 노드가 서기 궤적(0.3초)을 **토픽 `/dsr_moveit_controller/joint_trajectory`로 제어기에 직접**(액션 아님 — 10/6 박진용) → `safety/state` → 잠금 → 화면 '다시 시작'으로만 풀림 → 진행 확인부터. 웹캠 사람 감지는 없다 — **[출발] · [스캔] · [계속]을 누르는 사람이 영역 밖인지 확인**한다.
- **놓기:** 위치 제어, 블록마다 있음 · 없음 + 높이 확인, 오차는 측정값만. 목표 ±2 mm. 7 mm는 무너지는 경계(구조 유지 한계 = 검사기 규칙값)이지 허용 오차가 아니다.
- **설계도:** 기본 설계 4개(의자 Lv2 16 · 벤치 Lv1 11 · 책상 세운 다리 Lv4 9 · 책상 가운데 기둥 `004_DESK_PEDESTAL` 11 — 10/7 눕힌 다리 벽형을 대신함)를 CAD → 레시피로 DB에 미리 넣고(`made_by cad`, v1.0), 생성본은 검사 통과 시 자동 저장(`parent_id`, 버전 +0.1). 다음 블록 = sequence 첫 미배치. 조립 원점 = `robot.yaml` `assembly_origin` 하나(x 0.4261 · y −0.0725 · z −0.018 m — 10/6 다시 측정, 값은 robot.yaml이 정본).
- **블록 이름 · 레시피(E-52, 10/7 16시 PL — 한세교 작명 규칙 v2, `docs/작명규칙_설계_레시피_블록_v2_*.md`):** 블록 이름 = `<역할>_<부품 3자리>_<블록 2자리>`(예 `LEG_001_01`, 역할 `LEG` · `SEAT` · `BACK` · `BEAM` · `TOP` · `BASE` · `COLUMN`), 노드 사이 `block_id` = `<design_id 대문자>_<블록 이름>`. 레시피 = `<모델ID>_structure.json`(`cad_structure/1.0`) + `<모델ID>_recipe.json`(`cad_recipe/1.0`) + `_placements.csv`. **블록 이름에서 설계 이름을 잘라 내지 말 것** — `CheckProgress.design_id`로. 옮기기 마감 **10/8 저녁**(읽는 쪽 옛 · 새 둘 다 → 레시피 교체 → 옛 형식 빼기, W137~W141).
- **공급:** 1차(10/7)는 칸 6개 — 다 비면 `WAIT_SUPPLY` + "공급 채워 주세요" → 사람이 채우고 [계속](= `start`). 핵심(10/10~)은 흩뿌린 공급 영역(E-36) — 공급 관측 자세(W134)에서 `find_blocks`에 블록이 하나도 안 잡히면 `WAIT_SUPPLY` → [계속] → 다시 본다(10/7 PL). 2인용 조립은 보류.
- **DB:** 담당 HMI(황인재). 제품은 **PostgreSQL 16**(10/6 21시 확정 E-39). W088 전엔 `design_store` 한 겹이 JSON 파일 폴더로 돈다. 컨테이너는 웹 PC compose `mosquitto` · `db` · `web`(셋 다 황인재), 로봇 PC는 호스트.
- **PC 사이는 MQTT 다리 한 곳(E-27~E-30):** 로봇 PC `d2_bridge`가 ROS ↔ MQTT를 바꾼다. **ROS 쪽 이름 · 칸은 그대로** — task · 비전 · 로봇 동작 코드와 mock은 안 바뀐다(`mock_web_ui` → 이름만 `mock_bridge`). 다리 담당은 W121에서(안 황인재). 브로커 · 다리가 죽어도 로봇 PC의 키 · Ctrl+C · 펜던트 정지는 그대로.
- **웹(10/7 E-40 · E-41):** 웹은 frontend(Next.js 정적 + three.js, 브라우저에서 실행) · backend(FastAPI :8000) 둘, 컨테이너는 `web` 하나. frontend ↔ backend는 REST(`/api/designs` · `/api/robot`) · WebSocket `/ws`만, MQTT · DB · OpenAI는 backend(와 `voice.py`)만. 미리보기는 three.js 하나(PNG 없음), STT는 OpenAI Whisper API.
- **CI(E-34):** PR · main push마다 `tests/` pytest + 두산 의존 없는 패키지 colcon + ruff가 토큰 없이 돈다 — 로컬에서 `python3 -m pytest tests -q`로 먼저 본다. Claude 검토(①~⑧)는 팀원 PR 전부에서 돌고, '막음'이 없으면 자동 승인 → auto-merge(10/7).
- **스캔 복제(10/10~12):** 사람이 완성한 구조를 관측 자세 2~3곳에서 깊이 촬영 → 점군을 15·25·75 mm 격자에 맞춰 블록 자리 · 방향 → 가려진 블록은 받침 규칙으로 추정 → 블록 JSON → 검사 → 저장(`made_by scan`) → 사람이 치우고 [출발] → 복제. 이어 쌓기 · 확장이 아니다.
- **흩어진 블록 집기는 핵심(10/6 20시 E-36~E-38):** ① 찾기(`/d2/vision/find_blocks` 안 — 블록마다 위치 · yaw · 자세 · 윗면 높이 · 틈, 인식 방법 = YOLO seg + 깊이만 예비(E-38 · E-47, 10/7 PL — 데이터 규칙 `docs/YOLO데이터_수집라벨링규칙_*.md`, W133)) + 고르기(작업 판단 — **가장 잡기 쉬운 블록**, E-46: 다음 블록 자세 · 잡기에 맞고 틈이 넓고 겹치거나 기울지 않은 것) ② 겹친 블록뿐이면 위에 있는 것 ③ 밀어서 떼기만 챌린지 ②. 집을 블록 주변 틈 ≥ 2e + 18.2 mm(e = 2면 22.2, `find.min_gap_mm`, E-49). 한쪽이 걸쳐 기울어진 블록(`tilted`)은 건너뛰고 그것만 남으면 사람에게 알림, 집어 바로 놓기는 챌린지 ④(E-43, 구현 못 하면 지움). 세우기 동작(안 E-37): 눕힌 블록 끝 쪽을 FLAT_SHORT로 잡아 닫힘 축 90° → 내려놓으면 세움, FLAT_LONG이면 옆세움(2단계). 공급 칸 6개는 1차(10/7)만, 핵심은 흩뿌림 — 안 되면 칸으로 되돌림. 완료 기준 10개 중 8개(AC-9). 절차는 SDD §6.11.
- **챌린지(핵심 뒤 남으면, 어려운 것만):** ① 스캔 설계 요청대로 고치기 → ② 밀어서 떼기 → ③ 협동 번갈아 쌓기. 쉬운 것(음성 '멈춰' · 카메라 끊김 정지 · IK 검사)은 '나중에'(3D 미리보기는 10/7 E-40부터 핵심). 학습형(파인튜닝 · VLA) · 물리 시뮬 · 레고는 안 한다.

## 5. 일하는 방식

- **하루:** `/today 박진용` → 작업 → `/wrap W번호`. 처음 한 번은 `/start 박진용`.
- **말:** 박진용에게 쉬운 한국어로 짧게. 명령은 복사해 쓸 수 있게. 사실(측정값 · 좌표 · 이름)을 지어내지 않고, 문서와 다르면 묻는다.
- **다른 파트:** 그 파트 파일은 고치지 않고, 박진용이 보낼 짧은 메시지를 써 준다.
- **ROS 없는 계산 파일**(검사기 · 변환기 · 스캔 추론 · 생성 · 저장소)은 `pytest`로 로봇 없이 먼저 시험한다.
- **보고**(하루 끝 · 측정이나 결정이 생기면):
  ```
  [박진용 / 로봇 동작] 날짜
  - 한 것 / 잰 값·정한 것(숫자·단위) / 막힌 것 / 다른 파트에 필요한 것 / 변경 파일
  ```
- 30분 넘게 막히면 팀에 공유를 권한다.
