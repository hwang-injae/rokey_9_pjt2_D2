## 1. 원칙

1. **판단은 한 곳에서 한다.**

   | 무엇을 | 정하는 노드 | 보고 정하는 것 |
   |---|---|---|
   | 멈출지 | **정지 노드** | 정지 입력(화면 버튼 · 키 · Ctrl+C), 로봇 알람, 그리퍼 응답 없음. (카메라 연결 끊김은 챌린지 공통) |
   | 진행표(블록마다 놓였나) | **작업 판단**(task 노드 안 TaskPlanner) | 손목 블록 인식 결과 + 레시피. 블록 있음 · 없음 + 높이, 오차는 측정값만 |
   | **설계가 쌓을 만한지**(새) | **검사 묶음**(task 노드 안 DesignChecker, ROS 없는 계산) | 블록 JSON → 안정성 · 받침 · 틈 · 잡기 · 막힌 칸 · 작업영역. 통과하면 변환기 ①로 레시피까지 |
   | **무엇을 쌓을지**(새) | **사람**(화면 · 음성으로 설계 선택 · 출발) | AI가 만든 설계도 사람이 출발을 눌러야 로봇이 움직인다(SR-09) |
   | MoveIt2 장면 | **장면 관리** | 진행표(쌓인 블록 · 스캔한 실물 블록) + 쥔 블록 붙이기 · 떼기 |
   | DB에 무엇이 들어가나 | **HMI**(design_store) | 검사 통과한 설계는 자동 저장, 조립 결과는 작업 관리자가 넘긴 것 |

   비전은 관측 결과(있음 · 없음 · 높이 · 점군 추론)만 보낸다. 차례 판단(협동)은 없다.
2. **메시지 방식은 섞는다.** 요청-결과(집기 · 놓기, 이동, 진행 확인, 그리퍼, 장면 붙이기, 화면 명령, 정지, **설계 검사, 설계 꺼내기, 스캔 촬영 · 추론**)는 서비스 · 액션. 상태 방송(진행표 · 상태 · 스캔 결과 · 카메라 신호 · 그리퍼 상태)은 JSON 토픽. **JSON 덩어리를 주고받는 요청-결과는 `JsonQuery.srv` 하나로**(칸마다 srv를 만들지 않는다 — 팀 규칙 ② 과도한 구조화 금지).
3. **이름은 모두 `/d2/` 아래**: `/d2/hmi`, `/d2/safety`, `/d2/vision`, `/d2/task`, `/d2/motion`, `/d2/gripper`.
4. **단위.** 노드끼리 m · rad · 쿼터니언. 파일(레시피 · CSV)과 **블록 JSON은 mm**(설계 좌표계). `robot.yaml`은 키에 `_m`, 값 m(S-28).
5. **결과 형식.** `success` + `reason`(7장).
6. **JSON 규칙.** 맨 앞 `"schema": "이름/1"`, 시각 `stamp`(초). 형식을 바꾸면 `/2`.
7. **좌표**는 `base_link`. 설계 좌표(블록 JSON · 레시피)는 조립 원점(`assembly_origin`)으로 바꾼다 — 작업 판단 한 곳에서.
8. **블록 번호**는 레시피 block_id. 생성 · 스캔 설계의 block_id는 변환기 ①이 `<DESIGN>_B001`처럼 붙인다.
9. **장면은 장면 관리 노드만 고친다.**
10. **출발은 두 길 중 하나** — 화면 버튼 · 키(`hmi/command start`) 또는 음성(`hmi/intent start`). **잠금 풀기는 화면 '다시 시작'(`safety/resume`) 한 번**(S-24).
11. **멈출 때는 서기 궤적을 제어기에 직접** — **토픽 `/dsr_moveit_controller/joint_trajectory`** 로 보낸다(액션 `FollowJointTrajectory`는 실기에서 서지 않았다 — 10/4 R-01, 10/6 박진용).
12. **(새) 설계는 블록 JSON으로 오가고, 로봇에는 레시피로 간다.** 생성(HMI) · 스캔(비전)은 블록 JSON을 만들고, 검사 묶음이 통과시키며 레시피로 바꾼다. 로봇 쪽 노드(작업 판단 · 집기 · 놓기 · 장면)는 레시피만 안다 — 조립 엔진은 바뀌지 않는다.
13. **(새, E-27~E-29) PC 사이는 MQTT 다리 한 곳.** 웹 PC(화면 · 생성 · 저장소 · 음성)에는 ROS가 없다. 로봇 PC의 `bridge` 노드가 웹 쪽 토픽 · 서비스를 **대신** 한다 — 로봇 PC 노드는 웹이 ROS 노드인 것처럼 `/d2/hmi/…` 이름을 그대로 쓴다. 규칙은 [10장](#10-pc-사이-통신--mqtt-다리-e-27e-30-안). 토픽은 `d2/<ROS 이름>`, 서비스는 `…/req` · `…/res` + `req_id`.

- **돌리는 곳(E-26 · E-31):** **웹 PC**(ROS 없음) = 컨테이너 `mosquitto` · `db` · `web`(안, 호스트도 됨) + 호스트 음성. **로봇 PC** = 모두 호스트(브링업 · 집기 · 놓기 · 장면 · 그리퍼 · 정지 · 손목 블록 인식 + 스캔 추론기 · **task** · **bridge**). 컨테이너 `hmi` · `db-hmi`는 없다. ROS 2(CycloneDDS 60)는 로봇 PC 안에서만.
- **기록기 노드는 없다.** 작업 관리자가 CSV를 쓰고, 핵심에서 같은 칸을 `builds`로 넘긴다(HMI `design_store`가 DB에 씀 — 넘기는 길은 12장).
- 실행 이름(안)은 담당이 바꿀 수 있고, 바꾸면 이 표를 고친다.

## 4. 통신 표

> 아래 이름은 **로봇 PC 안의 ROS 약속**이다. '화면 · 음성'이 보내거나 받는 것은 **실제로는 다리 노드 `bridge`가 그 자리에서** 보내고 받는다(E-28). 웹 PC와 오가는 MQTT 토픽은 [10장](#10-pc-사이-통신--mqtt-다리-e-27e-30-안)의 표 하나로 정한다 — 이 장의 이름 · 칸이 바뀌면 10장도 같이 바뀐다.

## 8. 호출 순서

> 이름은 ROS 이름이다. 화면 · 음성 ↔ 작업 관리자 · 정지 노드 사이는 **다리를 거친다**(화면 → MQTT `…/req` → 다리 → ROS 서비스 → 답 → `…/res` → 화면). 순서 · 뜻은 같다.

### 8.1 저장된 설계 조립 — 블록 1개 (1차 판정 자동 모드와 같음)

```text
①  화면·음성  → hmi/command {cmd: select_design, design_id}  또는 hmi/intent {intent: select_design}  → 작업 관리자
②  작업 관리자 → hmi/get_design {design_id}                     → 웹 화면(design_store): 레시피·블록 JSON 답  (1차는 레시피 파일 직접)
③  화면·음성  → hmi/command {cmd: start} 또는 hmi/intent {intent: start}                              → 작업 관리자: 시작 점검(로봇·그리퍼·카메라·DB·조립 자리 비었나·공급) → 출발
④  작업 관리자 → motion/move_to {target: observe}              → 집기·놓기 (다 간 뒤 답)
⑤  작업 관리자 → vision/check_progress {block_ids}              → 손목 블록 인식
⑥  작업 관리자: 답을 작업 판단(TaskPlanner)에 → task/progress (진행표) → 장면 관리·화면
⑦  작업 판단: 다음 블록 = sequence 첫 미배치 (함수 호출) → {block_id, supply_slot, pick_pose, place_pose, grasp} / DONE
⑧  작업 관리자 → motion/pick_place (액션)                       → 집기·놓기: approach → gripper/command → scene/attach true → lift·move·place → attach false → retreat → 결과
⑨  SLOT_EMPTY가 이어져 공급이 다 비면 → WAIT_SUPPLY + 알림 supply_empty → 사람이 채우고 [계속] 버튼(= start) → ⑧부터
⑩  ④로 돌아가 블록마다 배치 확인 → 다 놓이면 DONE → RunLogger: CSV + builds(HMI로 넘김) → 알림 done
```

### 8.2 정지 (바뀐 곳: 서기 궤적이 토픽, 웹캠 없음)

```text
①  화면 정지 버튼·키 → safety/stop {source, reason}  → 정지 노드 → 답 success   (Ctrl+C는 움직이는 프로그램이 스스로 서기 궤적)
②  정지 노드: 멈출지 판단 — 정지 입력 / 로봇 알람 / 그리퍼 응답 없음 / ERROR   (카메라 연결 끊김 → 정지는 챌린지 공통)
③  정지 노드 → 토픽 /dsr_moveit_controller/joint_trajectory (서기 궤적: 지금 관절값, 0.3초)   ← 액션 아님(10/6 박진용)
④  정지 노드 → safety/state {stopped: true, locked: true, reason: STOP_REQUEST|ROBOT_ALARM|…}  → 작업 관리자 STOPPED, 화면 "멈췄어요", 집기·놓기 목표 취소(CANCELED)
⑤  사람 확인 → 화면 '다시 시작' → safety/resume → 잠금 풀림 → 작업 관리자가 바로 관측부터(8.1 ④)
```

- 펜던트 비상정지 · 두산 충돌 감지는 늘 작동. 2초 안에 안 서면 `move_stop`, 그래도 안 서면 펜던트.
- 다시 시작 버튼 옆에 '로봇 작업 영역에서 손을 빼고 누르세요'(HMI).

### 8.3 설계 생성 · 튜닝 (새, 핵심) — HMI 안에서 돌고 검사만 task를 부른다

```text
①  웹 글상자 [생성]  또는  음성 → hmi/intent {intent: request_design, text}  → 웹 화면: 문장을 보여 주고 사람이 [생성] 확인 (E-07)
②  design_gen: design_store에서 같은 family의 기본 설계·파생본(최근 3)·builds 결과를 찾음 (RAG)
③  design_gen → GPT-4o (튜닝 프롬프트, JSON Schema {template, params, count})   → 템플릿·숫자  → build_template → blocks/1
    템플릿으로 안 되면({template: null}) → GPT-4o (자유 생성 프롬프트, JSON Schema blocks) → blocks/1
    가구 2종 밖·범위 밖 → OUT_OF_SCOPE → 화면 안내, 끝
④  design_gen → task/check_design {blocks/1}                     → DesignChecker: 안정성(7 mm, 쌓는 도중) + 받침·틈·잡기·막힌 칸·작업영역 → ok면 변환기 ①로 레시피
⑤  ok 아니면: errors[].detail을 LLM 피드백으로 → ③부터 다시 (최대 2번) → 그래도 실패 → GEN_FAILED → 화면 이유 + 기본 설계 권함
⑥  ok면: design_store.save(designs: parent_id, version +0.1, made_by, gen_path, prompt, blocks, recipe, check)  → 화면: 미리보기(draw_png)·블록 수·검사 결과·버전 트리 → 알림 ready_to_start
⑦  사람이 [출발] → 8.1 ③부터 (작업 관리자는 get_design으로 레시피를 받음)
```

- ①~⑥은 로봇이 움직이지 않는다. 작업 관리자 상태는 IDLE/READY 그대로이고, 화면 알림만 `state/1`에 싣거나 화면이 직접 띄운다(HMI 안).
- 요청 → 저장까지 제안 ≤ 60초. 생성 중 표시 `generating`.

### 8.4 스캔 복제 (새, 핵심 10/9~12)

```text
①  사람: 완성한 구조물을 조립 작업영역에 두고 나감 → 화면 [스캔] → hmi/command {cmd: scan}  → 작업 관리자: SCAN_MOVE (시작 점검: 사람 밖·그리퍼 빔)
②  작업 관리자 → motion/move_to {target: observe}        → 집기·놓기 → 작업 관리자 → vision/scan_capture {pose_id: observe}        (SCAN_CAPTURE)
③  작업 관리자 → motion/move_to {target: observe_front}  → … → vision/scan_capture {pose_id: observe_front}
④  (선택) observe_side 도 같은 순서
⑤  작업 관리자 → vision/scan_infer {run_id}               → StructureScanner: 점군 → base_link → 작업면 위 높이 지도 → 격자(15·25·75 / 25·75 mm) → 블록 자리·방향 → 가려진 블록 받침 규칙으로 추정(inferred) → blocks/1   (SCAN_INFER)
⑥  작업 관리자 → task/scan_result {blocks, inferred_count, image_path}  → 화면: 실물 사진 ↔ 추론 설계 비교, 추정 블록 표시   (SCAN_REVIEW)
⑦  화면(HMI) → task/check_design {blocks}  → ok → design_store.save(made_by: scan, parent_id: 가장 가까운 기본 설계) → [저장]·[다시 스캔]·[출발]
⑧  사람: 구조물을 치움 → [출발] → 8.1 ③부터 (같은 조립 원점에 복제) → 끝나면 builds에 복제 결과(일치율·오차)
```

- 스캔 중 로봇은 카메라만 움직인다(블록을 잡지 않음). 사람이 영역 밖인 것은 [스캔]을 누르는 사람이 확인(SR-07).
- ⑦의 검사 · 저장은 생성 흐름(8.3 ④~⑥)과 같은 코드다.

### 8.5 음성으로 출발 (S-16, 그대로)

```text
①  음성 → hmi/intent {intent: start, design_id, text}  → 작업 관리자: 화면 출발 버튼과 똑같이 (IDLE·READY에서 시작 점검 뒤 출발, 운전 중이면 무시 + message)
```

- 확인 단계는 HMI 안에서. 작업 관리자에 확인 대기 상태 없음.

## 10. PC 사이 통신 — MQTT 다리 (E-27~E-30, 안)

웹 PC에는 ROS 2가 없다. **로봇 PC의 `bridge` 노드 하나**가 ROS ↔ MQTT를 바꾸고, 웹 PC의 **Mosquitto 브로커**(컨테이너 `mosquitto`, 1883)가 가운데 선다. 웹 백엔드(FastAPI) · 음성은 paho-mqtt로 브로커에 붙는다. 브라우저 ↔ 웹 백엔드는 WebSocket 그대로(브라우저는 브로커에 직접 붙지 않는다). 로봇 PC 안은 v1과 같다(CycloneDDS, `ROS_DOMAIN_ID` 60 — [env/README](env/README.md) 6장).

### 10.1 토픽 표 — ROS ↔ MQTT

| ROS 이름(4장) | MQTT 토픽 | 방향 | MQTT payload | retained | QoS |
|---|---|---|---|---|---|
| `/d2/task/state` | `d2/task/state` | 로봇 → 웹 | `state/1` JSON 글자 그대로 | ✅ | 1 |
| `/d2/task/progress` | `d2/task/progress` | 로봇 → 웹 | `progress/1` 그대로 | ✅ | 1 |
| `/d2/task/scan_result` | `d2/task/scan_result` | 로봇 → 웹 | `scan_result/1` 그대로 | ✅ | 1 |
| `/d2/safety/state` | `d2/safety/state` | 로봇 → 웹 | `safety_state/1` 그대로 | ✅ | 1 |
| `/d2/gripper/state` | `d2/gripper/state` | 로봇 → 웹 | `gripper_state/1` 그대로 | ✅ | 0 |
| `/d2/hmi/intent` | `d2/hmi/intent` | 웹(음성) → 로봇 | `intent/1` 그대로 — 다리가 ROS 토픽으로 낸다 | ✗ | 1 |
| `/d2/hmi/command`(서비스) | `d2/hmi/command/req` → `d2/hmi/command/res` | 웹 → 로봇 → 웹 | req `{"req_id","cmd","design_id","mode"}` → res `{"req_id","success","reason"}` | ✗ | 1 |
| `/d2/safety/stop`(서비스) | `d2/safety/stop/req` → `…/res` | 웹 → 로봇 → 웹 | req `{"req_id","source","reason"}` → res `{"req_id","success","message"}` | ✗ | 1 |
| `/d2/safety/resume`(서비스) | `d2/safety/resume/req` → `…/res` | 웹 → 로봇 → 웹 | req `{"req_id"}` → res `{"req_id","success","message"}` | ✗ | 1 |
| `/d2/task/check_design`(JsonQuery) | `d2/task/check_design/req` → `…/res` | 웹 → 로봇 → 웹 | req = `blocks/1` 객체 + `req_id` → res = `check_result/1` 객체 + `req_id` · `success` · `reason` | ✗ | 1 |
| `/d2/hmi/get_design`(JsonQuery, 로봇이 부름) | `d2/hmi/get_design/req` → `…/res` | 로봇 → 웹 → 로봇 | req `{"req_id","design_id"}` → res = `design/1` 객체 + `req_id` · `success` · `reason` | ✗ | 1 |
| `/d2/hmi/save_build`(JsonQuery, 로봇이 부름, 안 ⓐ) | `d2/hmi/save_build/req` → `…/res` | 로봇 → 웹 → 로봇 | req = builds 칸 + `req_id` → res `{"req_id","success","reason"}` | ✗ | 1 |
| (없음) | `d2/bridge/alive` · `d2/web/alive` | 양쪽 | `{"alive":true,"stamp"}` 1초마다, LWT `{"alive":false}` | ✅ | 1 |
| (없음, 안) | `d2/vision/scan_image` · `d2/vision/scan_cloud` | 로봇 → 웹 | JPEG 바이트(≤ 500 KB) · 다운샘플 PLY 바이트(복셀 3 mm, ≤ 2 MB) — 다리가 `scan_result`의 경로를 읽어 보냄 | ✗ | 1 |

- **규칙:** 토픽 = ROS 이름에서 맨 앞 `/`만 뺌. 상태(JSON 토픽)는 payload를 **그대로**(std_msgs/String 내용 = payload). **retained**는 ROS의 TRANSIENT_LOCAL 자리다 — 화면이 늦게 붙어도 마지막 상태를 받는다.
- **서비스 = `…/req` · `…/res` + `req_id`(UUID4).** 요청 payload = ROS 요청 칸들을 JSON 객체로(JsonQuery는 `request_json`의 객체 자체) + `req_id`. 응답 = ROS 응답 칸(+ JsonQuery는 `response_json`의 객체를 펼침) + `req_id`. 응답을 `mqtt.req_timeout_s`(5초) 안에 못 받으면 `TIMEOUT`. 같은 `req_id`가 두 번 오면 두 번째는 버린다.
- **다리는 변환만 한다.** 판단(멈출지 · 진행표 · 설계 검사)은 하지 않는다. 다리가 죽어도 로봇 PC 안 정지(키 · Ctrl+C · 알람 · 펜던트)는 그대로다(E-30 ⓑ).
- 이름 · 칸이 4~6장에서 바뀌면 이 표도 같이 바꾼다(payload는 같은 JSON이라 다리 코드는 대개 안 바뀜).

### 10.2 예시

```text
# 화면 출발 버튼
웹 → d2/hmi/command/req   {"req_id":"3f1c…","cmd":"start","design_id":"chair_v1.1","mode":"auto"}
다리 → ROS /d2/hmi/command → 작업 관리자 → 답 → 다리
다리 → d2/hmi/command/res  {"req_id":"3f1c…","success":true,"reason":""}
# 검사 묶음 호출
웹 → d2/task/check_design/req  {"req_id":"9a…","schema":"blocks/1","design_id":"chair_v1.1","family":"chair","blocks":[…]}
다리 → d2/task/check_design/res {"req_id":"9a…","success":true,"reason":"","schema":"check_result/1","ok":true,"min_margin_mm":12.5,"errors":[],"recipe":{…}}
# 작업 관리자가 설계를 꺼냄(로봇이 부름)
다리 → d2/hmi/get_design/req  {"req_id":"c2…","design_id":"chair_v1.1"}
웹 → d2/hmi/get_design/res    {"req_id":"c2…","success":true,"reason":"","schema":"design/1","design_id":"chair_v1.1",…,"recipe":{…},"blocks":{…}}
# 생존 신호
다리 → d2/bridge/alive (retained)  {"alive":true,"stamp":1791264600.5}      끊기면 브로커가 LWT {"alive":false}
```

### 10.4 브로커 (웹 PC, 컨테이너 `mosquitto`)

```text
# web/mosquitto/mosquitto.conf (안)
listener 1883 0.0.0.0        # 유선 LAN 안에서만. 인터넷에 열지 않는다
allow_anonymous true          # 인증은 10/8 결정(필요하면 password_file, 값은 .env)
persistence false
```

- 확인: 웹 PC `mosquitto_sub -h localhost -t 'd2/#' -v`, 로봇 PC `mosquitto_pub -h <웹 PC IP> -t d2/test -m hi`. 양쪽 모두 `apt install mosquitto-clients`.
- 다리 설정은 `robot.yaml` `mqtt.*`(9장). 웹 백엔드는 자기 설정(`web/backend/.env` → `MQTT_HOST=localhost`).

### 10.5 사진 · 점군 (안)

`scan_result/1`의 `image_path`는 로봇 PC 경로라 웹에서 못 연다. 다리가 그 파일을 읽어 `d2/vision/scan_image`(JPEG)로 보내고, 점군은 `d2/vision/scan_cloud`(PLY, 다운샘플)로 보낸다. 화면은 스캔 때만 **점군 창**(닫을 수 있음, three.js)을 띄운다(E-35). 크기 상한 · 다운샘플 간격은 10/9 비전 + HMI(12장).
