## 1. YOLO가 맡는 일 — "블록이 어디 있고 어떤 모양으로 보이나"까지만

```text
손목 컬러 사진 → YOLO seg → 블록마다 윤곽(마스크)   (예비 E-47: 실기에서 YOLO가 흔들리면 엣지 + 깊이 — 높이 지도로 층을 나누고, 같은 높이에 붙은 블록은 컬러 엣지로 가름)
                     ↓ (여기부터는 YOLO가 아님 — 깊이로 계산, SDD §6.11)
윤곽 안 깊이 → 작업면 기준 윗면 높이 15 · 25 · 75 mm → 자세(눕힘 · 옆세움 · 세움, 더 높으면 포개짐)
            → 양 끝 높이 차 ≥ 5 mm면 tilted(한쪽이 걸쳐 기울어짐, E-43 — 고르지 않음)
            → 긴 변 방향 = yaw → 중심 (x, y) → 양옆 틈 → find_blocks 결과
```

| 정할 것 | 안 | 이유 |
|---|---|---|
| 모델 종류 | **seg(윤곽) — 정함(PL 10/7)** · `yolov8n-seg` 또는 `yolo11n-seg`(가장 작은 n, 로봇 PC CPU 추론) | 박스는 기울기(yaw)를 모르고, 겹치면 두 박스가 거의 같아진다. 회전 박스(obb)는 yaw는 나오지만 가려진 곳까지 덮는다. seg는 보이는 모양 그대로라 X자 겹침 · 포개짐을 나눈다 — 그림 [YOLO 종류 비교](images/YOLO종류_비교_v1_100708.png) |
| 클래스 | **`block` 1개 — 정함(10/7 비전 동의, W086 결과 보고 필요하면 다시)** | ① 자세(눕힘 15 · 옆세움 25 · 세움 75 mm)와 기울어짐은 깊이로 확실히 나온다 — 같은 것을 YOLO에 또 시키지 않는다 ② 자세별로 나누면 150장이 셋으로 쪼개져 장수가 모자라고, 세움처럼 드문 클래스는 잘 안 배운다 ③ 포개짐 · 기울어짐처럼 애매한 블록에서 라벨하는 사람마다 클래스가 달라진다. 3개(`flat` · `edge` · `stand`)로 나누는 것은 깊이가 자주 틀릴 때의 대안 — 위에서 본 윗면이 75×25 · 75×15 · 25×15라 구분은 된다 |
| 입력 크기 | 640 × 480 그대로(`imgsz 640`) | 추론 때 카메라 설정과 같게. 약 500 mm 위에서 1 px ≈ 0.82 mm → 블록 긴 변 약 91 px, 짧은 변 18~30 px(W018) |

## 2. 수집 규칙 (W114 촬영, 10/7 오후)

### 2.1 카메라 · 자세

| 규칙 | 내용 |
|---|---|
| 카메라 | 손목 D435i, **컬러 640 × 480 + 컬러에 맞춘(align) 깊이 640 × 480**. 노출 · 화이트밸런스는 추론 때와 같게(자동 그대로) |
| 자세 | **observe_supply(W134)** 하나. W134가 아직이면 공급 영역 전체가 보이는 같은 높이(카메라 → 작업대 약 500 mm, ±5 cm)에서. **추론 때와 다른 높이 · 각도 사진은 섞지 않는다** |
| 같이 저장 | 같은 번호로 ① 컬러 PNG ② 깊이 16비트 PNG(mm) ③ 관절값 · 카메라 자세(TF) json — W022 녹화와 같은 묶음 |
| 화면에 넣지 않을 것 | 사람 손 · 팔(블록을 다 놓고 손을 뺀 뒤 찍는다), 로봇 그리퍼 그림자가 블록을 덮는 사진 |

### 2.2 장면 만들기 — 10장면 × 약 15장 = 약 150장

| 규칙 | 내용 |
|---|---|
| 흩뿌릴 영역(10/7 12시 PL) | **W134 때 observe_supply 화면에 다 들어오는 사각형을 테이프로 표시**한다. 촬영 · 시연 모두 이 안에만 흩뿌린다(학습한 범위 = 시연 범위). **10/7 박진용(W134):** 빨간 테이프 안쪽(세 변 테이프 + 바깥 한 변은 작업대 끝) **x 183~586 · y 142~337 mm(base_link) ≈ 40 × 19.5 cm**(사진으로 잰 값 ±1 cm), observe_supply 화면에 둘레 5~6 cm 여유로 들어옴. 로봇 쪽 · 조립 영역 쪽 모서리(x < 약 250 · y < 약 170)는 눕힌 블록을 집을 때 IK가 안 풀린다(몸에 가까움) — **학습 사진에는 있어도 되고, 시연 때는 그 모서리에 덜 둔다** |
| 장면 수 | 10장면(E-38). 장면마다 블록을 새로 흩뿌린다 |
| 블록 수 | **정하지 않는다(10/7 PL — 블록이 200개 이상이라 모자라지 않음).** 흩뿌릴 영역에 들어가는 만큼, 장면마다 다르게(적은 장면 · 빽빽한 장면을 섞는다) |
| 자세 섞기 | 대략 눕힘 절반 · 옆세움 ¼ · 세움 ¼ |
| 어려운 경우를 장면마다 넣기 | 포개짐(블록 위 블록) 2~3곳 · X자 겹침 1~2곳 · **한쪽이 다른 블록에 걸쳐 기울어진 블록 1~2개(E-43)** · 딱 붙은 두 블록(틈 없음) 1~2쌍 · 흩뿌릴 영역(테이프) 경계에 걸친 블록 1~2개 |
| 한 장면에서 여러 장 | 첫 사진을 찍고 → **위에 있는 블록부터 1~2개씩 걷어 내며** 다시 찍는다(로봇이 실제로 집는 순서와 같은 상태가 나온다) → 다 걷을 때까지 약 10~15장. **마지막 장은 블록 0개**(빈 영역 사진) |
| 조명 | 10장면 중 3장면 이상은 조명을 바꿔서(실내등 일부 끄기 · 블라인드 등). 시연장 조명을 모르니 한 가지 조명만 쓰지 않는다 |
| 빈 공급 영역 | 블록 0개 사진 — **따로 찍지 않고 장면마다 마지막 장(다 걷어 낸 뒤)을 쓴다** → 10장, 장면 번호 그대로(학습 · 검증을 나눌 때도 그 장면을 따라간다). WAIT_SUPPLY 상황 — 블록 없는 배경도 배워야 헛것을 안 찾는다(10/7 12시 PL) |
| 비슷한 사진 금지 | 같은 상태에서는 1장만. 녹화 영상에서 뽑을 때도 블록 상태가 바뀐 프레임만 |
| 녹화(W022) 사진 | 조립 영역의 정렬된 블록이라 흩뿌린 장면과 다르다 → 보조로, 전체의 ¼ 이하. **640 × 480이고 같은 높이(카메라 → 작업대 약 500 mm, 아래 방향)에서 찍은 것만 쓴다 — 아니면 뺀다**(10/7 12시 PL) |

**시간 어림:** 1장에 블록 걷기 포함 약 15초 → 150장 약 40분. W114는 10/7 오후(저녁까지)에 스캔 촬영과 같이 한다 — W134 교시 → 흩뿌린 장면을 먼저 찍는다(안).

## 3. 라벨링 규칙

| 규칙 | 내용 |
|---|---|
| 무엇을 | **화면에 보이는 블록은 어디 있든 전부** 라벨한다(공급 영역 밖, 조립 영역 블록 포함). 하나라도 빠지면 모델이 "블록인데 배경"으로 배운다 |
| 윤곽 | 블록이 **보이는 부분만** 따라 그린다. 가려진 부분을 짐작해 그리지 않는다. 위에서 보이는 옆면도 포함(블록 실루엣 전체) |
| 가려져 두 조각으로 보이면 | 큰 조각 하나만 그 블록으로 라벨 |
| 화면 끝에 잘린 블록 | 보이는 부분만 라벨 |
| 너무 많이 가려진 블록 | 사람이 보고 블록인지 모르겠으면 라벨하지 않는다(대략 보이는 면이 블록 윗면의 ⅓ 미만) |
| 도구(PL 10/7) | **Roboflow**(웹) — **민범진이 프로젝트를 만들고 라벨을 이끈다**(한석형 · 황인재 초대). 다 끝나면 민범진이 내보낸 데이터셋을 드라이브 `2_라벨_Roboflow`에 올린다. 프로젝트 종류 *Instance Segmentation*, 클래스 `block`. 블록을 클릭하면 윤곽을 따 주는 **Smart Polygon**(SAM 자동 윤곽, 단축키 S — 블록 가운데를 한 번 클릭하면 윤곽이 잡히고, 넘친 곳을 클릭하면 그 부분이 빠진다)을 쓰고 손으로 모서리만 다듬는다. 내보내기는 버전(Generate)을 만든 뒤 Export → **YOLOv8 또는 YOLOv11 형식**(윤곽 다각형 포함, Ultralytics). **버전을 만들 때 Preprocessing의 Resize(보통 640 × 640 늘이기)를 지우고 Augmentation은 넣지 않는다** — 640 × 480 사진이 찌그러지면 추론 사진과 달라진다. 증강은 학습 때 Ultralytics에서 한다(§4, 10/7 12시 PL). 올릴 때 검증 2장면은 Valid로 따로 올린다(§4). Roboflow가 내보내는 사진은 압축되므로 원본은 드라이브 것을 정본으로 둔다. 무료 판은 데이터가 Roboflow 학습에 쓰일 수 있다(설정에서 끌 수 있음 — 젠가 사진이라 문제는 없음) |
| 나누기 | **민범진 중심**, 한석형 · 황인재가 남는 장면을 장면 단위로 나눠 맡는다(누가 몇 장면인지는 민범진이 정함). 윤곽은 모두 약 750개(150장 × 사진 한 장에 평균 약 5개 — 걷어 내며 찍으므로 처음 개수의 절반쯤) — 자동 윤곽으로 한 사람이 다 하면 약 1.5~2시간(어림) |
| 검사 | 라벨한 사람이 아닌 사람이 장면마다 2장씩 다시 본다 — **빠진 블록 0개**가 기준 |

## 4. 나누기 · 학습 · 시험

| 규칙 | 내용 |
|---|---|
| 학습 · 검증 나누기 | **장면 단위로** 나눈다(사진 단위로 섞지 않음 — 같은 장면 사진은 서로 닮아 점수가 부풀려진다). 안: W114 10장면 중 학습 8장면 · 검증 2장면. **Roboflow에는 두 번에 나눠 올린다(10/7 PL)** — 검증 2장면 사진은 올릴 때 split을 **Valid**로, 나머지 8장면은 **Train**으로 고른다. Roboflow는 올릴 때 기본으로 사진 단위 70 / 20 / 10으로 섞으므로 이 설정을 꼭 바꾼다. Test는 0장(V-52 시험 장면은 따로). 버전을 만들 때(Generate) Train/Test Split의 **Rebalance는 누르지 않는다**(누르면 다시 사진 단위로 섞임). 검증 2장면은 올리기 전에 정한다(안: 조명 a 1장면 + 조명 b 1장면) |
| V-52 시험(10장면 ≥ 90 %) | **시험 데이터는 따로 빼 둔다** — 학습 · 검증에 한 번도 안 쓴 **새 장면 10개**(10/10~11 W086 실기 때 새로 흩뿌려 찍음, 장면 번호 21~30)를 `4_시험_V-52`에만 둔다. 학습에 쓴 장면으로 시험하면 답을 외운 문제를 다시 푸는 것이라 점수가 부풀려진다 |
| 학습 | **한석형(E-51), 황인재가 돕는다(10/7 PL).** Colab GPU, `imgsz 640`, 약 100 epoch, 약 1시간(E-38). 증강은 기본값(뒤집기 · 색 · 모자이크) + 회전(위에서 보는 사진이라 돌려도 같은 장면) — Roboflow에서는 증강하지 않는다(§3) |
| 추론 | 로봇 PC CPU — `find_blocks` 한 번에 사진 1장이라 속도 부담이 적다. W053에서 잰 CPU 여유 안에서 |

## 6. 정한 사람 · 때

모델 seg · 도구 Roboflow · 드라이브 저장(PL 10/7 09시), 클래스 `block` 1개(비전 동의 10/7 10시) · Roboflow는 민범진이 만들고 라벨을 이끌며 한석형 · 황인재가 남는 장면을 나눔(민범진 제안을 PL이 섞어 정함 10/7 10시). **10/7 12시 PL 검토 · 고침:** 담당 황인재(W133) · 자동 윤곽 이름 Smart Polygon · Roboflow 내보내기 때 Resize · 증강 끔 · 빈 사진 = 장면 마지막 장 · W022 사진은 640 × 480 · 같은 높이만 · 흩뿌릴 영역은 W134 때 테이프로 표시. 학습(`3_모델`)은 **한석형**(E-51), 황인재가 라벨링 · 학습을 돕는다(10/7 14시 40분 PL). 블록 수는 정하지 않음(블록 200개 이상, PL). 흩뿌릴 영역은 W134(박진용) 결과로 §2.2에 적었다 → **W133 완료(PL 10/7 14시 40분)**.
